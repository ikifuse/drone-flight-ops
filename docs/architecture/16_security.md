# 16. セキュリティ・秘密情報・トークン管理設計（16_security.md）

最終更新: 2026-09-14
プロジェクト: `drone-flight-ops`
フェーズ: Phase B2（詳細アーキテクチャ・実装前設計）

---

## 1. セキュリティ設計の根本原則

1. **クライアント完全非保持原則**: DIPS APIの `client_secret`、バックエンドAPIキー、秘密鍵等は、ブラウザ（JavaScript）やローカルストレージに絶対に配置・送信しない。
2. **最小権限・最小露出**: クライアントには一時的なセッショントークンまたは暗号化トークンのみを中継し、必要最小限の権限のみを付与する。
3. **監査ログ・バックアップへの機密混入防止**: トークンやパスワードは、コンソールログ、エラーログ、エクスポートJSON、GitHubコミットから完全にマスキング・除外する。

## 2. 秘密情報（Secrets）の階層別管理

```text
┌─────────────────────────────────────────────────────────────┐
│ [階層1] GitHubリポジトリ（正本コード）                      │
│  - 秘密情報は1行たりともコミットしない (.gitignore徹底)     │
│  - 環境変数テンプレート (.env.example) のみを配置           │
└──────────────────────────────┬──────────────────────────────┘
                               │ (デプロイ時CI)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ [階層2] バックエンド環境（Cloudflare Workers Secrets）       │
│  - DIPS_DRS_CLIENT_SECRET, DIPS_FPR_CLIENT_SECRET 等        │
│  - wrangler secret put によるエッジ側KMS暗号化保存          │
│  - サーバーレス実行時のみメモリ展開                         │
└──────────────────────────────┬──────────────────────────────┘
                               │ (暗号化通信・セキュアCookie/ヘッダー)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ [階層3] クライアント環境（ブラウザ / IndexedDB）            │
│  - 短期Access Token / 暗号化Refresh Token のみ一時保持      │
│  - XSS対策: サードパーティスクリプトの排除、CSP適用         │
└─────────────────────────────────────────────────────────────┘
```

## 3. トークンライフサイクル管理

### 3.1 DIPS Access Token & Refresh Token
- **Access Token**:
  - 有効期間: DIPS仕様に準拠（通常数十分〜数時間）。
  - 保管場所: クライアント側メモリ内（ステート管理ストア内）。ブラウザを閉じると自動消滅。
- **Refresh Token**:
  - 保管場所: セキュアなIndexedDB内専用キーストア（またはWorkers側セッション）。
  - 有効期限切れハンドリング: 自動リフレッシュ失敗時は即座に「再ログイン（認可）」を要求。

### 3.2 ログ・エクスポートからのマスキング
- ログ出力ラッパー（`LoggerService`）により、`token`, `secret`, `authorization`, `password`, `key` を含むオブジェクトフィールドを自動的に `***MASKED***` に置換。
- バックアップJSONエクスポート機能（`exportBackupJson()`）では、認証トークンテーブルおよびキーストアを明示的にエクスポート対象外（Filter-out）とする。

## 4. 資格情報失効・ローテーション手順

- **即時ログアウト**: パイロットがログアウトを実行した際、ローカルのTokenストアを完全消去し、DIPS側のRevocation Endpoint（規定されている場合）へ失効通知を発行。
- **credentialローテーション**: 国交省側で `client_secret` が更新された場合、`npx wrangler secret put DIPS_CLIENT_SECRET` を実行するだけで、クライアントアプリの再配布・再ビルドなしに即座に新キーへ移行可能。
