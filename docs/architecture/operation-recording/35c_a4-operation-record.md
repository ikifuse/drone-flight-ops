# 35c. A4運航・日常点検記録の実物と生成単位

最終更新: 2026-09-18\
由来: 99.2 §5・§10、最新Drive実物の直接確認、旧帳票設計のGit履歴。A4の詳細・因果の正本。

## 1. 旧帳票から最新実物へ至った理由

**当初運用（HISTORICAL）**: 旧GASの日常点検帳票は横長の左右No.1／No.2、各7明細の構成だった。8明細目、機体交代、新しい場所等では次ブロックへ進み、原本をコピーした日付・連番シートへ最終保存で自動記入した。99.2 §5は、分割先それぞれへ基本情報・飛行前点検・該当明細を入れ、最後の飛行後点検を対応先すべてへ反映したと記録する。[35d](35d_operation-finalization-and-write-boundary.md)が参照する旧コードでも、7件単位の割当と各割当への点検記入を静的に確認した。

**既存Docsの再設計（HISTORICAL）**: `5d51315`のADR-0007 §2.9と旧18は、内部データが印刷枠へ縛られる問題を避け、正規化したデータをReportUnitへ射影する案とした。A4縦へ日常点検・飛行記録・点検整備サマリーを入れ、可変行数でPage 2以降へ続ける設計だった。旧18の「5または6飛行」という旧制約の説明と、99.2／旧保存コードの7明細は一致しないため、旧説明を現物の行数証拠には使わない。

**問題と実物調整**: 内部の正規化だけでは、人が直接確認・印刷する帳票の読みやすさは確定しない。99.2はAI作成の改行・列幅・行高等をオーナーが手作業で整えた経緯を保持する。2026-09-18の追加指示で、下記のDriveファイル1つを最新実物と指定した。古い試作、旧main、旧Excelコピーで置き換えず、その実ファイルを直接読み取った。

**変更理由**: 現在はそのA4縦1枚の見通しを優先する。内部データの正規化と帳票生成の責務分離は残すが、存在しない点検整備サマリーの追加、文字縮小による8行目の押込み、自動続紙を現在仕様として残さない。詳細整備の独立責任は[36](../maintenance-storage/36_aircraft-maintenance-records.md)、内部モデルと帳票モデルの分離は[18](../18_reports.md)へ接続する。

## 2. 最新実物から直接確認したこと

**EVIDENCE/EXAMPLE**: Google Drive上の「無人航空機・飛行記録・日常点検記録_確認用_1飛行」。確認日2026-09-18、取得した更新時刻2026-09-16 04:31:07.725 UTC。完全一致タイトルは検索結果内で1件。原本タブ「原本_無人航空機・飛行記録・日常点検記録」1枚、36行×39列（A:AM）。これは完成済みアプリの生成結果や正式実飛行の証拠ではない。

直接のSheetsセル・書式読み取りに加え、**同じ実ファイルから今回取得した**XLSXの書式情報とPDFの視覚確認を補助に用いた。古いローカルExcelは使用していない。実物・書式・設定への編集は行っていない。実名・登録記号・非公開Drive ID・画像そのものは本書へ転載しない。

**観測の限界（VERIFY-S6-A4-PRINT）**: 今回の汎用PDF取得APIのMediaBoxは612×792pt（Letter）だった。A4設定を保持した印刷経路・倍率までこのPDFで検証済みとはしない。ブラウザー操作環境が利用できずGoogle Sheets印刷プレビューと実紙印刷は未確認。A4縦1枚はオーナー指定・現在99.2・上記pageSetupに基づく設計ベースラインとして保持し、API出力差を理由にPENDINGへ戻さない。確認した文字サイズ等は今回の実物の値であり、PDF内の縮尺や代替フォントを同じ数値と断定しない。

## 3. その後の運用判断による現在ベースライン

**CURRENT-ACCEPTED**: 現在99.2 §5／§10に到達済みとして保持される以下の運用を採用する。§2の1枚を眺めて推定した生成規則ではない。

| 論点 | 現在の意味 | 根拠の種類 |
|---|---|---|
| 1枚の成立 | A4縦1枚・固定7明細。基本情報、前後点検の左右比較、飛行記録、記事・不具合・処置を維持 | 最新実物＋§5の採用判断＋今回のオーナー指示 |
| 正式保存 | 最後の送信／保存でA4原本をコピーし、`YYYY.M.D`、`YYYY.M.D_2`、`YYYY.M.D_3`等の日付・連番の**物理シート**へ自動記入 | §5・§10の後続運用判断。実物1枚からは証明できない |
| 分割の条件 | 8明細目、機体交代、新しい場所等では新しい連番A4シートへ進める。文字を縮めたり同一シートをPage 2へ延長したりしない | §5の旧分割運用を新A4へ引き継ぐ判断 |
| 各分割先 | 同一機体で7明細を超える場合も、各シートへ基本情報・飛行前点検・該当明細・最終飛行後点検を入れ、単独で記録を読めるようにする | §5、旧割当処理の確認。最新実物上の複数シート生成試験ではない |
| 保存先と印刷 | 04の正式運航記録を直接確認・印刷できるSpreadsheetとして残す。Google Sheets標準の印刷／PDFを利用できるようにする | §5・§10の運用判断 |
| PDF | アプリから必要時に出力し07のPDF側へ保存。運航のたびに必ず自動PDFを作るとはしない | §5。07の詳細階層は本書で確定しない |

シートを分ける規則から、Mission／Flight／FlightLeg／AircraftSwitchのID・基数を確定しない。[35a](35a_flexible-flight-and-details.md)の柔軟な1飛行には内部明細を保持し、7枠はDomainの上限ではない。場所変更と同一エリアの意味、日付・区切りの詳細判定も旧18の「場所ID」や「午前／午後」の例だけで固定しない。

最終送信の入力・操作は[35b](35b_normal-operation-and-final-save.md)、A4と同時にBAT個体履歴・使用機体累計等を完成させる保存責任と重複防止は[35d](35d_operation-finalization-and-write-boundary.md)。人手による飛行後の転記を必要とする方式へ戻さない。

## 4. 未確定事項と再検討の境界

- **PENDING-S6-A4-DETAIL**: 補助者0人時の空欄／「なし」等、年度替わりと長期・複数環境でのSpreadsheet分割、テンプレート版・項目対応、日付境界・同名競合を含む自動複製アルゴリズム。実物の寸法観測と製品の全入力長への対応保証を分ける。
- **PENDING-S6-OPERATION-SCHEMA**は35a、再送時に同じ割当を二重生成しない契約は35dへ委譲する。日付・連番タブを使うことと、その採番処理の完全な実装仕様は別である。
- **VERIFY-S6-A4-PRINT**: A4実寸・フォント・改行・余白の印刷経路検証。長い氏名／複数補助者／長文不具合等を入れた場合の読める状態も未検証。実物を改変せず将来の検証用出力で確認する。
- 現在ベースラインは変更可能だが、人が整えた配置をAIの一般論だけで再設計しない。変更時は実物・理由・影響・オーナー判断を[規約03](../../guidelines/03_design-evidence-and-causality.md)に従って追跡する。
