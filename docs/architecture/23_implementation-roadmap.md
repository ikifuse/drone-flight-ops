# 23. Phase C 実装ロードマップとマイルストーン（23_implementation-roadmap.md）

最終更新: 2026-09-14
プロジェクト: `drone-flight-ops`
フェーズ: Phase B2（詳細アーキテクチャ・実装前設計）

---

## 1. 実装の基本方針（安全な段階的積み上げ）

一度に巨大なアプリケーションを構築するのではなく、**「各段階で必ず動作するアプリが存在し、テストをパスしながら機能を拡張する」**インクリメンタルなロードマップを策定します。

```text
C0: 基盤・PWA Shell 構築
 └─► C1: ローカルDB (Dexie.js) & ドメイン層
      └─► C2: 現行運航フロー再現 (点検〜離着陸〜BAT交換)
           ├─► C3: バッテリー台帳 & 機体累計管理
           ├─► C4: スプレッドシート外部台帳同期 & 競合解決
           └─► C5: 地図・FlightArea (MapLibre & GeoJSON)
                └─► C6: DIPS Adapter (Mock) & 通報状態管理
                     ├─► C7: DIPS実接続中継 (Workers Proxy)
                     ├─► C8: 国交省様式 PDF/CSV 帳票出力
                     └─► C9: オフライン強化 & 実機結合検証
```

---

## 2. 実装フェーズ詳細仕様

### Phase C0: 基盤・PWA Shell 構築
- **目的**: Vite + TypeScript + PWA の最小実行可能スケルトンを構築。
- **実装範囲**: プロジェクト初期化、PWA Service Worker登録、基本レイアウト、高コントラストCSSトークン。
- **完了条件**: iPhone SafariおよびPixel Chromeでホーム画面追加ができ、フルスクリーンオフライン起動すること。

### Phase C1: ローカルDB & ドメインモデル実装
- **目的**: 現場自律稼働のためのデータ永続化基盤を確立。
- **実装範囲**: `src/domain/` の型定義、Dexie.jsデータベース定義、Storage API（`persist()`）要求、手動JSONエクスポート/インポート。
- **完了条件**: ブラウザリロード後も作成したデータが完全に維持・復元されること。単体テスト100%パス。

### Phase C2: 現行運航フロー完全再現
- **目的**: 現行GASアプリのコア運航体験（準備→飛行前点検→離陸→着陸→BAT交換→飛行後点検→完了）を再現。
- **実装範囲**: `OperationStateMachine`、片手打刻UI、タイマー計測、8回以上フライト対応。
- **完了条件**: 通信なしの状態で、離着陸・BAT交換を連続して行い、フライトログが正確に記録できること。

### Phase C3: バッテリー個体台帳 & 機体累計管理
- **目的**: 自作アプリ最大の強みであるバッテリー個体追跡を完成。
- **実装範囲**: 7本バッテリー管理画面、累積サイクル計算、所感記録、機体累計時間自動合算。
- **完了条件**: フライト完了ごとに各バッテリーの累積時間・回数が正確に加算・表示されること。

### Phase C4: Googleスプレッドシート外部同期 & 競合解決
- **目的**: 運航記録の外部台帳二重化と手修正尊重プロトコルの実装。
- **実装範囲**: `SyncQueue`、Google Sheets API/GAS連携、手修正上書き防止ロジック、再送冪等性。
- **完了条件**: 電波復帰時にワンタップで同期され、スプレッドシートの手修正が上書きされないこと。

### Phase C5: 地図・FlightArea描画（MapLibre GL JS）
- **目的**: 国土地理院タイルを用いた現場飛行範囲作成機能の実装。
- **実装範囲**: 地図表示、円形（中心＋半径）操作、多角形ポリゴン描画、GeoJSON生成、キャッシュ機構。
- **完了条件**: 現場予定エリアを画面上に描画・保存し、オフライン時でも事前キャッシュ地図が表示されること。

### Phase C6: DIPS Adapter (Mock) & 通報状態マシン
- **目的**: DIPS通信境界の確立と、安全な状態遷移UIの実装。
- **実装範囲**: `DipsNotificationStateMachine`、`MockDipsAdapter`、通報キュー、誤認防止安全UI。
- **完了条件**: 通報成功確認済みになっても「飛行可能」と誤認させない安全確認画面が動作すること。

### Phase C7: DIPS実接続中継 (Cloudflare Workers Proxy)
- **目的**: DIPS APIの正式credentialを用いた中継プロキシの結合（利用資格確認後）。
- **実装範囲**: Workers OIDCトークン交換、CORSプロキシ、Secrets保管。
- **完了条件**: DIPSテスト環境または本番環境との間でトークン取得・計画通報が成立すること。

### Phase C8: 国交省様式 PDF/CSV 帳票出力
- **目的**: 法定飛行日誌および日常点検記録の印刷・提出用帳票生成。
- **実装範囲**: `pdf-lib` による国交省様式1・2・3のPDFレンダリング、CSV出力。
- **完了条件**: オフライン環境でもブラウザ内で国交省標準様式に完全準拠したPDFが生成・保存できること。

### Phase C9: オフライン強化 & iPhone/Android実機総合検証
- **目的**: 現場本番運用に向けた最終実機検証と信頼性確認。
- **実装範囲**: 実機での電波遮断テスト、強制終了復帰テスト、並行運用テスト（Shadow Run）。
- **完了条件**: 実際の飛行現場で現行アプリと並行運用し、3回以上のフライトで完全一致・不具合ゼロを確認すること。
