## 1. テストピラミッドと検証境界

「実装後にまとめてテストする」のではなく、各モジュール実装と同時に継続的自動テストを実施します。

99.2 §0・§1の再移植では、その前段となる[保存・出力の確認と実装開始ゲート](23_implementation-roadmap.md#12-保存出力を確かめてから依存実装へ進むゲート)を明示した。設計実物を見て不足を発見する検証と、実装後の動作テストは区別する。[実物証拠の扱い](../guidelines/03_design-evidence-and-causality.md#4-実物確認と設計への反映)に従い、試作が存在するだけで受入済みとしない。以下のテスト計画を実行したという意味でもない。

```text
       ▲
      / \        [E2E・実機テスト] (iPhone 13 / Pixel 6a実機検証)
     /   \       - 現場片手タップ操作、PWAホーム追加、オフライン起動
    /─────\
   /       \     [統合テスト (Integration)] (Vitest / Playwright)
  /         \    - 同期キュー、Dexie.js永続化、DIPS Mock通信、手動修正競合
 /───────────\
/             \  [単体テスト (Unit)] (Vitest) - 最も厚く高速に実行
                 - 運航状態マシン、バッテリーサイクル計算、機体累計時間、
                   FlightAreaジオメトリ計算、法令様式マッピング
```

## 2. 主要テスト領域と検証項目

### 2.1 単体テスト（Unit Tests）
- **運航状態マシン**: 通常案内の不正な遷移（点検未完了からTAKEOFF_READY、飛行中にBAT交換等）は拒否する一方、実際に発生した離着陸の記録は拒否せず警告・監査付きで保持すること（[13a](state-machines/13a_operation.md)、[13c](state-machines/13c_takeoff-readiness.md)）。
- **計算エンジン**: ミリ秒打刻からの飛行時間（分・秒）算出、累積時間の丸め処理が正確であること。
- **バッテリー生涯追跡**: サイクル数の加算、充放電深度の追跡ロジック。
- **FlightArea計算**: [17](17_map-and-airspace.md) の `POLYGON` / `CIRCLE` / `BUFFERED_LINE`、名前付き座標、円半径・線形バッファ片側距離のバリデーション。API未確認の線形バッファを勝手にPolygon変換送信しないこと。

### 2.2 統合テスト（Integration Tests）
- **オフライン・同期キュー**: 通信切断状態でジョブが安全にキューイングされ、オンライン復帰時に順次送信されること。
- **DIPS Adapter Mock**: C6ではManual/Mockの状態・確認方法・疑似成功表示を検証する。C7 Optional実装時に認可コードフロー、トークンリフレッシュ、受付番号受領、4xx/5xx・結果不明照合を追加する。API資格情報をC6テストの前提にしない。
- **スプレッドシート競合解決**: 手動修正フラグがある場合に、端末側の過去データで上書きされないことの検証。

### 2.3 実機検証（iPhone 13 & Pixel 6a）
- **iPhone 13 (iOS Safari / WebKit)**:
  - 「ホーム画面に追加」によるフルスクリーン起動。
  - `navigator.storage.persist()` の挙動と永続化ステータス表示。
  - 画面ロック復帰時のタイマー計測の継続。
  - 屋外高コントラスト表示の視認性。
- **Pixel 6a (Android Chrome)**:
  - PWAインストール、オフライン起動。
  - GPS現在地測位の精度確認。
  - バックグラウンド切替時のアプリ復帰。

### 2.4 DIPS手動通報・飛行計画台帳・フォールバック検証（B2.2追加・必須テスト項目）
Phase Cの実装・検証において、DIPS API非依存性および台帳・手動フォールバックが確実に成立することを担保するため、以下の12項目を対応Phaseで自動／手動検証する。実APIを要する9および10のAPI側検証はC7 Optional実装時に行い、C6では共通契約とManual/Mockで検証する。

1. **DIPS API credential完全非存在テスト**:
   - APIキー、OIDC設定が一切存在しない環境で、飛行計画（POLYGON/CIRCLE/BUFFERED_LINE、日時、機体、操縦者）をエラーなく作成・保存できること。
2. **不変スナップショット先行保存および外部台帳同期テスト**:
   - DIPS通報（API/手動問わず）前に、ローカルへ不変 `submission_snapshot` が確実に永続化され、Googleスプレッドシート「DIPS飛行計画台帳」へ同期ジョブが登録・同期できること。またSheets障害中・同期待ちでもDIPS通報自体がブロックされないこと。
3. **手動入力支援画面・コピー機能テスト**:
   - 手動支援画面がDIPS Web実画面順で表示され、日時・場所・高度・登録記号・操縦者・許可番号の転記テキストを1タップで正確にコピーできること。機体/操縦者/許可の登録済Picker、目的/空域/方法checkbox、構造化保険、Geometry作図の案内をコピーだけで代替せず、API JSONを表示・生成・要求しないこと（[25b](dips-flight-plan/25b_manual-web-mapping.md)）。
4. **手動通報実施の打刻記録テスト**:
   - 操縦者が「DIPSへ手動通報した」ボタンを押した際、`manual_submitted` ステータスおよび通報日時がローカルDBおよび台帳へ確実に記録されること。
5. **手動通報とDIPS確認済みの誤認防止・確認方法テスト**:
   - `manual_submitted` の状態では「DIPS受理確認済み」とは表示されず、操縦者がDIPS画面の受付番号を入力（`displayed_id`）、またはDIPS飛行計画一覧の一致を目視確認（`flight_plan_list_match`）して初めて `dips_confirmed` に昇格すること。番号表示がない場合（`dips_plan_id: null`）でも一覧照合が記録されていれば安全に完了できること。
6. **不変スナップショット保護テスト**:
   - FlightPlanの内容（日時や機体）を後から編集しても、過去に通報した `DipsSubmission` の `submission_snapshot` が破壊・上書きされずに保持されること。
7. **訂正・取消・再通報履歴テスト**:
   - 計画変更による新リビジョン起票時に、旧提出に `superseded_by_id`、新提出に `supersedes_id` が設定され、取消時には取消日時・理由が記録されること。
8. **オフライン計画作成と復帰同期テスト**:
   - 電波圏外（機内モード）で飛行計画を作成・提出確定し、オンライン復帰後にスプレッドシート「DIPS飛行計画台帳」へ自動フラッシュ同期されること。
9. **API後付け移行テスト**:
   - 手動通報データが蓄積された環境に、後からDIPS API設定を注入した場合でも、データ移行作業を必要とせず、新規計画からAPI通報がシームレスに動作すること。
10. **共通ドメインモデル整合テスト**:
    - 手動通報アダプター（`ManualDipsAdapter`）とAPIアダプター（`ApiDipsAdapter`）が全く同一の `FlightPlan` / `DipsSubmission` 型を消費・生成すること。
11. **DIPS Mockの表示誤認防止テスト**:
    - `MockDipsAdapter` での通報成功時に、画面上に「[MOCK] 疑似通報完了」と明記され、本番通報成功と誤認させる表現が一切存在しないこと。
12. **実飛行（Mission/Flight）との予定実績紐付け追跡テスト**:
    - 運航開始時に飛行計画を選択し、飛行日誌側の `planned_submission_id` からDIPS飛行計画台帳の該当行へ双方向で相互参照・監査対比できること。

## 3. 再編後の正本と追加の境界検証

仕様を本書へ複製せず、[Domain](domain-model/README.md)、[状態・離陸評価](state-machines/README.md)、[Sheets台帳](dips-submission/24a_submission-and-sheets-ledger.md)、[項目判定](dips-flight-plan/25d_requirement-validation.md)、[出力](output/README.md) に対応する検証を置く。通報要否は150mちょうど、未確定、非特定、公式障害と通常圏外を区別し、通報なしでも実離陸の記録が保持されることを確認する。C1では本タスクによる機能追加・実装を行わない。
