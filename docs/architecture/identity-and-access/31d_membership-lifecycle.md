# 31d. 所属終了・再所属・過去実績の保持

最終更新: 2026-09-25\
由来: 99.2 §2【離任・再所属】【会社利用】【アプリ管理者】【未確定】、基準12a / 12f / ADR-0007。\
主要責務: 環境への所属のライフサイクルと記録継続。所属の概念は[31a](31a_person-account-and-environment.md)、アクセス判定は[31b](31b_roles-and-access-control.md)。

## 1. 人物の退職状態から環境への所属終了へ

**当初状態（HISTORICAL）**: 基準12aはPersonnelにACTIVE / INACTIVE / RETIREDを置いた。[12f](../domain-model/12f_common-lifecycle-id-and-audit.md)と[ADR-0007 §2.7](../../decisions/ADR-0007-normalized-masters-and-business-reporting.md)は、過去履歴の参照を壊さないためMasterを物理削除せず論理状態で扱うと定めた。

**問題・検討案・変更理由**: 99.2の複数環境所属では、ある会社の離任は他環境でも人物が存在しなくなることを意味しない。人物削除や人物全体の退職として扱う方法では、過去の飛行・点検・監査の参照や他環境での活動と混ざる。長期未使用、臨時講師の空白期間、スポット勤務、休職だけで自動退職にする方法も、実際の所属終了を表さないため採らない。元の物理削除禁止・履歴保持の理由を維持し、終了対象を環境への所属へ具体化する。

**現在到達点（CURRENT-ACCEPTED）**: 退職・離任は対象環境との所属終了であり、人物削除ではない。過去の飛行・点検・監査記録を保持し、その環境の新規運航候補から外す。別環境の所属を同時に終了させる意味ではない。非活動期間だけによる自動退職は行わない。

**処理の方向（CURRENT-PROPOSAL）**: 権限者が対象環境で明示的に退職・離任へ変更した時だけ所属終了として扱う方向。原本は離任UI・処理権限・offline反映を未確定と明記しているため、「権限者」を管理者だけ／操縦者も可能等へ今回固定しない。管理者の追加解除規約だけから離任操作の権限を導かない。

## 2. 履歴の内容を詰めた経緯

**根拠・検討の進展**: 原本は人物・所属・資格の分離を実Driveの5タブで確認し、「退職・離任履歴」も含めた（実物の位置づけとVERIFYは[31a §3](31a_person-account-and-environment.md#3-資格の分離と確認用5タブ)）。過去実績を残すだけでなく、離任時にどの環境・役割・アカウントだったかを追える履歴内容を検討した。

**候補（CURRENT-PROPOSAL）**: 人物ID、氏名、対象環境、当時のGoogleアカウント、離任日、終了時役割、当時把握したDriveアクセス区分、技能証明情報等を保持する案。正確な列・履歴の物理構造は**PENDING-S2-MEMBERSHIP**。当時把握したDrive区分の記録は監査用の時点情報であり、現在のGoogle共有権限の第二正本ではない。列案の存在をもって全列を必須にせず、[12fの操作主体と人物の監査接続](../domain-model/12f_common-lifecycle-id-and-audit.md#6-操作アカウントと人員の監査接続pending-c1-schema)と照合する。

## 3. 再所属とGoogle共有を別に扱う

**問題・現在到達点（CURRENT-ACCEPTED）**: 同じ人物の再所属時に新人物を作ると、過去履歴との連続性が分断される。このため既存人物IDと過去履歴を維持し、所属を再有効化して、現在必要な役割を再設定する。過去の役割が全て自動復活する方式として扱わない。再所属の具体的な画面・保存表現はPENDING-S2-MEMBERSHIPに残す。

**実アクセスの例外（CURRENT-ACCEPTED）**: 所属終了とDrive共有解除、再所属と再共有は別処理であり、Google側で共有を変更する。アプリ内で離任としてもGoogle共有が残ればDriveから直接見える可能性がある。このため所属終了をアクセス遮断完了とは表示・解釈しない。理由となる三層と外部仕様確認は[31b §1・§2](31b_roles-and-access-control.md#1-二重権限管理を採らないまでの因果)に一元化する。

**PENDING-S2-MEMBERSHIP**: 離任UI、実行できる役割、offline時の反映と復帰後の扱い、履歴列、再有効化の物理schemaは未確定。離任・再所属の意味が到達済みであることと、処理方式が確定したことを区別する。自動権限取消や即時全端末失効の仕組みを推測で追加しない。

同じIDの中で、次の2つを別の判断として扱う（2026-09-25の整理。IDは改名・分割しない）。

- **操作面（後続の画面・権限の判断）**: 離任UI、離任を実行できる役割（§1の「権限者」を誰にするか）、offline時の反映と復帰後の扱い。実行できる役割は業務上の権限に関わるため、画面設計の段階でオーナー判断の対象になりうる。C1全体の開始条件ではない。
- **物理schema（C1の該当型を固定する前の技術設計）**: 所属履歴の列、再有効化の保存表現、Person／UserAccount／OperationalEnvironment／EnvironmentMembershipの対応IDと基数。§1〜§3の到達済みの意味（離任＝所属終了、過去記録の保持、同じPersonでの再所属、旧役割を自動復活させない）を満たすようAI側が設計し、[31a §2](31a_person-account-and-environment.md#2-現在の概念境界とorganization)のPENDING-S2-IDENTITY・[12f](../domain-model/12f_common-lifecycle-id-and-audit.md#6-操作アカウントと人員の監査接続pending-c1-schema)と照合する。「誰に離任ボタンを許すか」の答えを待たずに設計できる範囲であり、両者を1つのオーナー質問にしない。

## 4. 組織所有と事業継続の未確定境界

**発端・検討案**: 会社利用で個人私用アカウントの所有へ依存する問題から、原本は組織管理Googleアカウントを使う方向を示した（[31a §4](31a_person-account-and-environment.md#4-会社利用と環境切替へ詰めた内容)）。My Drive所有者交代とShared Driveを、アプリ管理者の交代とは別の物理所有・事業継続の論点として残した。Shared Driveが組織所有であるという確認事実だけでは、本アプリでの方式選定が終わったことにはならない。

**2026-09-23に到達した範囲（CURRENT-ACCEPTED。[31a §4](31a_person-account-and-environment.md#4-会社利用と環境切替へ詰めた内容)・[34a §9.4](../presentation/34a_setup-and-environment-entry.md#94-会社団体はホームからその会社で使うgoogleアカウントで追加する)）**: 会社・団体環境の正本データは、その会社・団体で使うGoogle／Workspaceアカウント側の保存領域へ置く。参加者個人の私用Driveを会社データの正本にしない。上記の発端にある「組織管理Googleアカウントを使う方向」は、この範囲で確定した。

**所有者交代と通常の人の入れ替わりを分ける**: 一般参加者の退職・離任は§1の所属終了であり、会社環境の所有者交代ではない。アプリ管理者の追加・解除も[31b §3](31b_roles-and-access-control.md#3-初期管理者追加解除最後の1人)の役割変更であり、所有者交代ではない。

**PENDING-S2-OWNERSHIP**: 残る未決は次の2つに限る。①会社環境の物理保存方式（My DriveかShared Driveか。法人My Driveの所有者交代、Shared Driveの利用・移行・運用方式を含む）。②会社アカウントの廃止、Workspace／ドメイン移行、Shared Driveへの移行、合併・事業譲渡等、事業継続上の特殊な場面での承継。アプリの最後の管理者保護は[31b §3](31b_roles-and-access-control.md#3-初期管理者追加解除最後の1人)であり、ファイル所有者交代ができることや事業継続の復旧完了を保証する規則ではない。既存[障害復旧設計](../19_failure-recovery.md)の保証範囲も拡張しない。

## 5. 検証・監査で残す境界

離任後も過去の飛行・点検・監査から人物へ辿れること、対象環境で新規候補から外れること、他環境の所属を巻き込まないこと、空白期間を退職にしないこと、再所属で同じ人物IDを維持すること、Google共有の残存と所属状態を取り違えないことを照合する。未確定のoffline反映・操作主体・所有方式を確定する前に処理を実装しない。[ADR-0016](../../decisions/ADR-0016-environment-membership-and-access-separation.md)は変更判断の記録、詳細因果は本書、移管と検査の索引は[Step 2監査](../../migration/99-2-step-2-causal-audit.md)に置く。
