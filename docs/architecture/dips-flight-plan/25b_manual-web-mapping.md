# 25b. DIPS Web手動入力支援

最終更新: 2026-09-15\
状態: 設計整合（C1未着手）\
主責務: Web画面順の登録選択・構造化入力・コピー・通報確認UI\
入口: [DIPS Flight Plan設計群](README.md)

## 1. 入力済情報を再利用するManual経路

[通報入力支援原則](25_overview.md)に従い、`submission_snapshot → DipsManualEntryViewModel` を直接生成する。API JSONは経由せず、利用者にも見せない。`ManualAssistanceData` は旧15の名称であり、現在の正式名を `DipsManualEntryViewModel` に統一する。

[26の2026-09-14実画面観測](../26_dips-web-ui-verification.md)は、登録済情報の選択＋checkbox＋数値/日時＋地図Geometryを中心とする入力構造を示す。以下はその観測を根拠として採用する**新アプリの設計要件**であり、未観測のDIPS内部仕様や最終通報成功を証明するものではない。

| 入力領域 | 採用する要件 | 証拠 |
|---|---|---|
| Aircraft | 登録済機体Pickerで複数機体選択。登録記号・型式/名称・メーカー・第一種/第二種認証の識別情報を表示し、DIPSの登録済機体選択へ案内 | OBSERVED 26§2.1 |
| Pilot | Personnel Pickerの複数操縦者。氏名・機体紐付け・技能証明で照合し、電話/メール/証明番号の毎回再入力を避ける | OBSERVED 26§2.2、複数時詳細PENDING-WEB-03 |
| Purpose | 業務/業務外の複数選択。その他理由は該当時のみ表示。内部目的（操縦練習、国家資格練習、趣味空撮、観光PR、不動産、工事進捗、屋根/外壁確認、測量、災害確認、研究/検証等）から選択を支援 | OBSERVED 26§2.3、外部コード変換25c |
| Airspace / Flight Method | 目的と独立した複数checkbox。該当なしと具体選択の整合を確認。緊急用務空域は飛行直前確認へ分離 | OBSERVED 26§2.4–2.5、17 |
| Permission | 登録済許可の番号・発行日・期間・カテゴリーを照合して選択。自動反映範囲は未確認 | OBSERVED 26§2.10、PENDING-WEB-02 |
| Insurance | 保険会社・商品・加入有無・対人/対物を構造化入力。InsurancePolicyからロードして計画override可能 | OBSERVED 26§2.11 |
| Contact | 自アカウント/申請書/操縦者の連絡先情報源を区別。SubmissionActor、Actual Pilot、Contactを同一人物と仮定しない | OBSERVED 26§2.13、[12a](../domain-model/12a_organization-and-personnel.md) |
| 日時 | 開始/終了・時間を構造化して確認。定期/複数日拡張を阻害しない。日別時刻・通報ID・変更取消単位は保留 | OBSERVED / PENDING-WEB-04 |
| Geometry | POLYGON / CIRCLE / BUFFERED_LINEを視認・再作図支援。頂点/経路/中心/半径/幅と高度を提示 | OBSERVED 26§2.7、一般型[17](../17_map-and-airspace.md) |

登録済Pickerは選択すべき識別値を提示し、checkboxは日本語の選択候補と確認状態を表示する。テキスト入力へは1タップコピー、数値/日時へは適切な単位・書式のコピーを提供する。すべてを自由文の貼り付けにしない。DIPS画面へ自動入力・自動送信したと表示しない。

## 2. ViewModelの責務とデータ契約

| グループ | Snapshotから生成する表示内容 |
|---|---|
| 基本情報 | `flightPlanId`, `revision`, 計画名称、場所名称、開始/終了表示、飛行時間、複数日の展開余地 |
| `aircraftSelections[]` | 機体ID、登録記号、モデル/メーカー、認証情報、Picker照合案内（単一機体へ固定しない） |
| `pilotSelections[]` | Personnel ID、氏名、技能証明、必要時連絡先、主操縦者表示（単一人物へ固定しない） |
| 目的/空域/方法 | 日本語の複数選択ラベル、該当するその他理由、立入管理・係留・カテゴリー確認案内 |
| 地図 | 中心/頂点/経路の座標、半径またはバッファ片側距離、高度AGL/MSL、速度、形状識別。GeoJSON貼付けを要求しない |
| 許可/保険 | 許可番号・期間、保険会社/商品、加入状態、対人/対物限度額（無制限表示） |
| 連絡/安全 | 連絡先情報源と対象者、補助者人数、安全・気象・点検・緊急手順等の確認項目、特記事項 |
| 操作 | `dipsWebUrl`、項目コピー、手動通報打刻、番号確認/一覧照合確認 |

旧15の `plannedStartTimeFormatted`, `plannedEndTimeFormatted`, `locationName`, `coordinatesText`, `radiusMetersText`, `altitudeAglText`, `aircraftRegistrationMark`, `aircraftModel`, `pilotName`, `pilotLicenseNumber`, `flightPurpose`, `flightType`, `permissionNumber`, `dipsWebUrl` の情報は上記グループに保持する。単一機体・操縦者の属性は配列の各要素へ移す。具体的な実装型はC6でこの契約へ合わせ、C1に画面実装を追加しない。

## 3. 手動DIPS Web入力支援（DipsManualEntryViewModel）設計

## 4. 転記と通報確認の操作

### 4.1. 画面仕様
- **上部ナビゲーション**:
  - 「DIPS 2.0 Webを開く」ボタン（タップでブラウザの別タブを起動）。
  - 注意メッセージ: *「※DIPS側へ自動送信はされません。登録済情報を選択し、必要なテキスト項目をコピーして、DIPS画面で入力・確認・通報してください。」*
- **入力支援カード（テキスト値はコピー、Picker/checkboxは照合用。以下は匿名・架空の表示例）**:
  1. **飛行日時**: `2026/10/20 10:00 〜 2026/10/20 12:00` ［コピー］
  2. **飛行場所名称**: `〇〇県〇〇市〇〇町 現場A` ［コピー］
  3. **代表座標 (緯度, 経度)**: `33.456789, 129.876543` ［コピー］
  4. **飛行範囲半径**: `150m` ［コピー］
  5. **計画高度 (対地高度 AGL)**: `30m` ［コピー］
  6. **機体登録記号**: `JU324XXXXXXX` ［コピー］
  7. **操縦者氏名 / 技能証明番号**: `操縦者A / 第XXXXX号` ［コピー］
  8. **飛行目的**: `空撮` ［コピー］
  9. **飛行形態**: `昼間飛行・目視内飛行` ［コピー］
  10. **許可承認番号**: `国空航第XXXXX号` ［コピー］
- **下部通報ステータス記録エリア**:
  - **アクション1: 「DIPSへ手動通報した」ボタン**:
    - タップすると `MANUAL_SUBMITTED` が打刻され、「手動通報実施を記録（DIPS登録確認待ち）」表示へ遷移。
  - **アクション2: 「DIPS通報確認完了」操作エリア**:
    - **パターンA（受付番号確認時）**: DIPS完了画面等に受付番号が表示された場合、番号（例: `PLN-20261020-XXXX`）を入力して「番号で確認完了」をタップ。`confirmation_method: 'displayed_id'` で `DIPS_CONFIRMED` へ昇格。
    - **パターンB（飛行計画一覧目視照合時）**: 国交省Web手動操作で受付番号が明示されない場合でも、DIPS「飛行計画一覧」画面で日時・機体・範囲の一致を目視確認し、「一覧照合で確認完了」をタップ。`dips_plan_id: null` のまま `confirmation_method: 'flight_plan_list_match'` で安全に `DIPS_CONFIRMED` へ昇格。
    - いずれの場合もGoogleスプレッドシート台帳へ確認ステータス・確認方法・番号（取得時のみ）が反映される。

---

状態そのものの定義・遷移は[13b DIPS状態](../state-machines/13b_dips-submission.md)、台帳反映は[DIPS Submission Ledger](../dips-submission/README.md)を正本とする。受付番号確認・一覧照合は別の確認方法として記録し、単なるコピー完了や自己申告の打刻だけでDIPS確認済みにしない。

## 5. 全88項目の入力元・自動化集計と動的評価

全88項目について、「現場で人間が毎回入力しなければならない項目」と「システムが自動補完・再利用する項目」の旧設計では下表の概算を置きました。分類は重複し、終了日時・面積などNo.1〜88の独立行ではない値も含むため、88項目の排他的な正確集計ではありません。数字は入力削減の設計意図を残す参考値であり、実際の件数は25dの評価結果から算出します。

| 入力元分類 | 項目数 | 主な内訳 |
|---|:---:|---|
| **MASTER から自動取得** | **34** | 機体スペック（18〜25）、操縦者プロファイル（5〜12）、許可承認詳細（47〜54）、保険台帳（60〜65）、通報者情報（56〜59） |
| **PRESET から初期ロード** | **14** | 飛行目的（28〜31）、安全措置（66〜67）、飛行マニュアル（68〜69）、基本高度・速度（37〜40）、飛行空域プリセット |
| **DERIVED（自動計算・導出）** | **4** | 終了日時、補助者人数（14）、飛行時間（36）、面積 |
| **PLAN_INPUT（現場確定入力）**| **12** | 計画名（2）、開始日時（35）、実総重量（26）、航続時間（27）、実飛行経路（41〜45）、特記事項（76）、安全確認チェック（70〜75） |
| **SUBMISSION_METADATA** | **14** | 計画ID（1）、重複フラグ（3, 85〜86）、システム名（87〜88）、DIPS受付番号（82）、状態コード（79〜81, 83〜84） |
| **CONDITIONAL（特定条件時）** | **10** | 各種「その他」理由入力（29, 30, 33, 67, 69）、取消理由（84）、許可連絡先（50〜54） |

> [!IMPORTANT]
> **「現場入力約12項目」は固定値ではありません（動的算出値）**:\
> 上記の「約12項目」は、マスター（機体、操縦者、許可承認、保険）が完全に事前登録されており、かつ「その他」理由や特殊条件が発生しない場合の**典型的なケースにおける参考値**です。\
> 操縦者の連絡先電話番号がマスター上で未登録の場合や、飛行目的に「その他」を選択した場合、あるいは新機体で包括許可書番号を個別上書きする場合は、現場での手入力・確認項目数は増減します。\
> アプリは「固定12項目フォーム」として画面をハードコードするのではなく、[25dの `DipsFieldRequirementEngine`](25d_requirement-validation.md) が文脈に応じて動的に必須性と入力責任を判定します。

## 6. 観測未確定事項と確認境界

青い `i` アイコンは項目ヘルプとして扱い、必須性は[25d](25d_requirement-validation.md)で判定する。機体選択時重量反映、許可複数選択、民間技能認証欄、一覧表示、繰り返し、代理権限、最終validationは[26のPENDING一覧](../26_dips-web-ui-verification.md)を継承する。GeometryのDIPS API可否は[25c](25c_api-payload-mapping.md)と分離する。
