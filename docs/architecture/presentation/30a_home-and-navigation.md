## 1. ホーム画面の目的と設計意図

本システムのホーム画面は、**「現場スマートフォンで操作しやすく、操作数や誤操作を抑え、必要情報を確認しやすいUI」** を実現するため、役割の異なる4つの入口を明確に分離した構造を採用します。

過去の検討では「通常飛行」＋「設定変更」の2入口案や、「通常飛行」「飛行履歴・出力」「各種設定・管理」の3入口案が存在しましたが、DIPS通報と実飛行が同時とは限らず（数日前の事前通報、事務担当者による事前通報など）、時間差や分業が存在する現場の実情に即し、**「新しく計画を作る入口」と「すでに通報済みの計画から実飛行へ進む入口」を分離**したホーム4大入口へ整理・確定しました（`CURRENT-ACCEPTED`）。

---

## 2. ホーム4大入口の役割固定（CURRENT-ACCEPTED）

ホーム画面には以下の4つの大入口のみを配置し、深い階層を挟まずに目的の操作へ最短で到達できる導線とします。

```text
┌─────────────────────────────────────────────────────────────┐
│                    [ アプリケーションヘッダー ]             │
│                    現在環境名（タップで環境切替）           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ①［ 新 規 飛 行 ］                                        │
│     - 新しい飛行計画の作成、Geometry入力、DIPS通報          │
│     - 通報成功時点で共有飛行リストへ即時反映                │
│                                                             │
│  ②［ 飛 行 リ ス ト ］                                      │
│     - DIPS受付済みの待機・進行中計画の作業キュー            │
│     - カード選択 → DIPS通報内容確認 → 飛行前点検へ         │
│                                                             │
│  ③［ 飛 行 履 歴 ・ 出 力 ］                                │
│     - 完了した過去飛行記録（04運航記録・06証跡）の閲覧      │
│     - 日常点検日誌確認、PDF帳票出力、KMLエクスポート        │
│                                                             │
│  ④［ 各 種 設 定 ・ 管 理 ］                                │
│     - 人員、機体、バッテリー、運用環境等のマスター台帳管理 │
│     - 権限に応じた環境設定・システム管理                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 各入口の詳細責務

1. **①［新規飛行］（CURRENT-ACCEPTED）**:
   - **役割**: 新しい飛行計画を起票し、飛行範囲（Geometry）を設定してDIPSへの通報（手動通報またはAPI自動通報）を完了させる入口。
   - **遷移**: 飛行計画入力 → 地図Geometry編集 → 通報内容確認 → DIPS通報実施・応答受領。
   - **通報成功後の挙動**: DIPS側の正常受付（`API_CONFIRMED` または `DIPS_CONFIRMED`）が確認された時点で、計画は直ちに共有飛行リストへ登録される。続けて「飛行前点検へ進む」か「後で飛行する（ホームへ戻る）」を選択可能。
2. **②［飛行リスト］（CURRENT-ACCEPTED）**:
   - **役割**: すでにDIPSで正常受付され、これから実飛行を行う予定、または現在進行中の作業対象を扱う作業キュー（Working Queue）入口。
   - **遷移**: 共有飛行リスト一覧 → 対象カード選択 → DIPS通報内容確認 → ［飛行前点検へ］または［飛行中止／削除］。
3. **③［飛行履歴・出力］（CURRENT-ACCEPTED）**:
   - **役割**: 過去に完了した飛行セッション（`MISSION_COMPLETED`）の記録を検索・閲覧し、各種帳票を派生出力する入口。
   - **遷移**: 過去日誌一覧・検索 → 日常点検・運航記録閲覧 → A4 PDF出力 / KML出力。
4. **④［各種設定・管理］（CURRENT-ACCEPTED）**:
   - **役割**: 人員（操縦者・関係者）、機体、バッテリー、場所プリセット等のマスターデータおよび運用環境の設定を行う入口。
   - **遷移**: マスター選択 → 各種台帳閲覧・編集（権限に応じた操作）。

## 3. ホーム画面のシンプル化原則（CURRENT-ACCEPTED）

- **未処理件数バッジの非表示（CURRENT-ACCEPTED）**:
  - ホーム画面には「未完了○件」「未処理バッジ」等の件数表示を必須としません。
  - ホーム画面自体の情報密度を抑え、認知負荷を軽減します。予定件数や現在のDIPS通報状態の確認は、②［飛行リスト］の内部で行う設計とします。

---

## 4. 全体ナビゲーション原則（CURRENT-ACCEPTED）

1. **最短突入原則**:
   - 現場の操縦者が飛行を開始する際は、ホームから［飛行リスト］→ 対象カードタップ → ［飛行前点検へ］の最小ステップで運航状態マシン（`13a_operation.md`）へ突入できるようにします。
2. **中間確認画面の排除**:
   - 飛行リストからカードを選択した後は、余分な中間の「計画サマリー画面」などを挟まず、DIPS通報内容の表示画面へ直行します。
3. **常設編集ボタンの排除**:
   - 通報済み計画の通常詳細画面に、安易な「計画編集」ボタンを常設しません。日時や飛行範囲を変更する場合は、DIPS側の通報変更・再送信を伴う別処理として安全に誘導します。

---

## 5. 通常運航時のマスターその場登録 UX（CURRENT-PROPOSAL）

現場で新規飛行計画を作成する際、操縦者・機体・バッテリー・飛行場所等のマスターが未登録であっても、事前に設定画面を探しに戻ることなく入力を継続できるようにする現在有力なUX案です。

- **「選択 → なければ新規登録 → 元フロー復帰」導線**:
  - ドロップダウンやPickerの末尾に［＋ 新規登録］導線を配置。
  - タップすると最小限の入力モーダルが開き、登録完了後は直ちに元の入力画面へ復帰して自動選択状態とする。
  - これにより、初回セットアップ時に全機体・全バッテリーの事前登録を強制しなくても、現場で段階的にデータを蓄積できます。

## 6. 運用環境表示および切替 UI（CURRENT-PROPOSAL）

- **現在環境の明示**:
  - 画面最上部のヘッダー領域に、現在操作中の「運用環境名（例: 個人環境／会社環境）」を表示します。
  - 環境名をタップすることで環境切替モーダルが開き、所属する別環境へ切り替え可能とします。
- **単一環境所属時の最適化**:
  - ユーザーが1つの運用環境にのみ所属している場合は、環境名の常時表示や切替導線を非表示・簡略化し、画面領域を節約します。
- **環境ライフサイクルの正本境界**:
  - 環境の作成・参加・権限判定に関する論理正本は [02. 運用環境・アカウント・所属ライフサイクル設計](../identity-and-access/02_environment-and-personnel-lifecycle.md) を参照し、Presentation側は表示および切替トリガーのみを担当します。
