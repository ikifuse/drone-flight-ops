# 30c. 共有飛行リスト画面仕様（30c_shared-flight-list-ui.md）

最終更新: 2026-09-18
状態: Phase C0完了・Phase C1未着手（99.2設計検討正本反映）
正本責任: Presentation / 共有飛行リストUI仕様（規約30b準拠）

---

## 1. 画面の目的（Purpose）

- **作業キューとしての本質（CURRENT-ACCEPTED）**:
  - 本画面は、過去の飛行日誌を保管・閲覧する監査台帳ではなく、**「これから飛行する予定／現在進行中の作業対象」** を管理する軽量な共有作業キュー（Working Queue）です。
  - DIPS通報が正常受付された計画をチームや他端末間で共有し、現場操縦者がスムーズに引き継いで点検・運航を開始できるようにします。

---

## 2. 進入条件・前提状態（Entry Conditions）

- **進入経路（CURRENT-ACCEPTED）**:
  - ホーム画面の ②［飛行リスト］ をタップすることで本画面へ遷移する。
- **前提データ（CURRENT-ACCEPTED）**:
  - 運用環境の共有飛行リスト台帳（Google Drive / Sheets）または端末ローカルキャッシュに、作業対象の飛行計画レコードが存在すること（0件の場合は空状態メッセージ「予定されている飛行計画はありません」を表示）。

---

## 3. 表示情報（Displayed Information）

本画面は上部の絞り込みフィルター領域と、飛行計画カードのリスト表示領域で構成されます。

### 3.1. 飛行計画カードの基本表示5項目（CURRENT-ACCEPTED）

各カードには、現場で人が即座に計画を識別するために不可欠な以下の**基本5項目**を表示します。

```text
┌─────────────────────────────────────────────────────────────┐
│ ［カード］                                                  │
│  ① 予定日時: 2026-09-20 09:30 〜 11:30                     │
│  ② 飛行場所: ○○海岸 第1工区（35.xxxx, 139.xxxx）           │
│  ③ 使用機体: EVO Lite+ (JU3269B165D2)                       │
│  ④ 人　　員: 操縦者: 山田 太郎 ／ 通報者: 佐藤 事務        │
│  ⑤ DIPS状態: ［通報済み・重複なし］                         │
└─────────────────────────────────────────────────────────────┘
```

1. **① 予定日時**: 飛行開始予定時刻 〜 終了予定時刻。
2. **② 飛行場所**: 場所名称（または代表座標・プリセット名）。
3. **③ 使用機体**: 機体愛称および機体登録記号。
4. **④ 人員（操縦者 ／ 通報者）**: 現場で操縦を担当する人物名、およびDIPS通報手続きを行った人物名（※通報者と操縦者が別人の場合も一目で判別可能）。
5. **⑤ DIPS状態**: 待機中の計画におけるDIPS通報ステータス表示。

> [!NOTE]
> **計画名（Plan Name）の非表示（CURRENT-ACCEPTED）**:
> 画面の情報密度を抑え、現場で最も重要な日時・場所・機体・人員の視認性を最優先するため、現時点の設計ベースラインではカード上に「計画名」を含めない方針としています。

### 3.2. 状態文言の文脈分離（CURRENT-ACCEPTED）

混乱や誤認を防ぐため、通報手続きの直後画面と、待機リスト上での状態文言を明確に分離します。

| 表示場面 | 状態文言 | 意味・文脈 |
|---|---|---|
| **DIPS通報完了直後画面** | **`通報完了・重複なし`** | 当該通報トランザクションがDIPS側で正常受付され、他計画との重複がないことの即時通知。 |
| **共有飛行リストのカード** | **`通報済み・重複なし`** | DIPSへの通報が受理され、待機中である状態表示。 |
| **共有飛行リストのカード** | **`通報済み・重複あり`** | DIPS通報は完了したが、他計画との空域・時間重複が通知されており、飛行前の確認・調整を要する状態表示。 |

### 3.3. 上部フィルター候補（CURRENT-PROPOSAL）

リスト最上部には、現場での素早い絞り込みを支援する以下の切り替えタブを現在有力なUI案として配置します。

- ［すべて］: 作業対象のすべての計画を表示（初期選択候補）。
- ［自分が操縦］: ログインユーザー本人が操縦者として割り当てられている計画のみを抽出。
- ［自分が通報］: ログインユーザー本人が通報手続きを行った計画のみを抽出。
- ［重複あり］: 空域重複が通知されている計画のみを抽出。

---

## 4. 初期値／自動入力（Initial Values & Auto-fill）

- 画面進入時のフィルター初期選択は ［すべて］ とします（`CURRENT-PROPOSAL`）。
- カードの並び順は、原則として「予定日時の昇順（直近の予定が最上部）」とします（`CURRENT-ACCEPTED`）。

---

## 5. 主操作／副操作（Primary & Secondary Actions）

カードをタップすると、余分な中間サマリー画面を挟まずに、直接その計画の「DIPS通報内容（日時、範囲、機体、人員、空域）」を確認する詳細画面が開きます（`CURRENT-ACCEPTED`）。

```text
┌─────────────────────────────────────────────────────────────┐
│                 [ DIPS通報内容確認画面 ]                    │
│                                                             │
│   予定日時・場所・機体・操縦者・通報者・空域図・許可条件    │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ ★ 主操作: ［ 飛 行 前 点 検 へ ］                    │  │
│  └───────────────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ ☆ 副操作: ［ 飛 行 中 止 ／ 削 除 ］                 │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

1. **主操作: ［飛行前点検へ］（CURRENT-ACCEPTED）**:
   - 画面下部に最も目立つボタンとして配置。
   - タップすると現場運航状態マシン（`13a_operation.md`）の点検ステップへ突入し、実飛行セッションを開始する。
2. **副操作: ［飛行中止／削除］（CURRENT-ACCEPTED）**:
   - 主操作と離れた位置に控えめに配置（誤タップ防止）。
   - 急病、天候悪化、スケジュール変更等により飛行を行わない場合に、計画の中止処理を行い、リストから整理する。
3. **常設編集導線の排除（CURRENT-ACCEPTED）**:
   - 通常詳細画面に安易な「編集」ボタンを常設しません。通報済み計画の日時や空域を変更する場合は、DIPS側の通報変更・再送信が必要な別処理として安全に案内します。

> [!NOTE]
> **通報直後画面との操作の対比（CURRENT-ACCEPTED）**:
> - **DIPS通報直後画面の操作**: ［飛行前点検へ］（続けて直ちに飛ぶ）／ ［後で飛行する］（一旦ホーム等へ戻る）
> - **飛行リスト側の操作**: ［飛行前点検へ］／ ［飛行中止／削除］

## 6. 遷移先（Transitions）

- ［飛行前点検へ］押下時 → [13a. 現場運航状態マシン](../state-machines/13a_operation.md) の `PREFLIGHT_INSPECTION` 画面へ遷移。
- ［飛行中止／削除］押下時 → 中止理由選択ダイアログを表示後、中止処理を完了して飛行リスト一覧へ復帰。
- ヘッダーの［戻る］押下時 → ホーム画面へ復帰。

---

## 7. 戻る／取消／削除の扱い（Back, Cancel, Delete Handling）

- **詳細確認からの戻る**:
  - DIPS通報内容確認画面から［戻る］を押下した場合は、データ変更を行わずに飛行リスト一覧画面へ戻る。
- **計画の中止・削除**:
  - 制度上可能な範囲でDIPS側取消を行うが、通信断や急病等でDIPS取消が完了しない場合であっても、現場端末の作業リストが永久に滞留することを防ぐため、アプリ作業キュー上での「現場中止記録」を可能とする。

---

## 8. 保存・更新対象と反映タイミング（Data Targets & Timing）

1. **DIPS通報成功時の即時掲載（CURRENT-ACCEPTED）**:
   - 飛行計画のDIPS通報が成功（`API_CONFIRMED` または `DIPS_CONFIRMED`）した時点で、**直ちに**共有飛行リスト（Google Drive共有台帳および端末ローカルキャッシュ）へ掲載される。
   - ※通報直後画面で「後で飛行する」を押した時まで登録を待つような遅延反映は行わない。
2. **非同期引継ぎの成立（CURRENT-ACCEPTED）**:
   - 事務担当者等がオフィスで事前通報した計画は、共有台帳（Google Drive `06_DIPS関連`）に書き込まれることで、後日現場の操縦者の端末へ共有・配信される。
3. **作業完了時の整理（CURRENT-ACCEPTED）**:
   - 実飛行が完了（`MISSION_COMPLETED`）した計画、または中止された計画は、作業キューとしての飛行リストから整理・除外される。

---

## 9. 権限差による表示・操作制御（Permission Variations）

- **三層権限分離の維持（CURRENT-ACCEPTED）**:
  - Presentation層において、業務役割（Operational Role）とアプリ機能権限（App functional permission）を勝手にマージ・自動結合しません。
- **UI表示制御の課題（PENDING-C1-UI-PERMISSIONS）**:
  - 閲覧専用権限者（Viewer）に対するボタン非活性化や、操縦者に指名されているユーザーのみに［飛行前点検へ］を許可する等の具体的なUI連動条件は、[01. 三層権限モデル](../identity-and-access/01_three-tier-permissions-and-roles.md) との整合を保ちつつ、後続の実装設計フェーズ（C1）で精査・確定します。

---

## 10. Online / Offline 時の挙動差異（Connectivity Variations）

1. **データ権威の意味論（CURRENT-ACCEPTED）**:
   - Google Drive / Sheets上の作業台帳が共有飛行リストの論理的正本であり、端末ローカルキャッシュは「表示高速化および電波圏外でのOffline支援」として位置づけられます。
2. **オフライン現場での動作（CURRENT-ACCEPTED）**:
   - 通信圏外の現場であっても、事前に同期された端末キャッシュから飛行計画を選択し、［飛行前点検へ］を押してオフラインで運航を開始できます。
   - ※端末に計画が一度もキャッシュされていない完全新規のオフライン状態では、共有台帳からの取得は行えません（キャッシュ存在が前提）。
3. **オンライン復帰時の挙動（CURRENT-ACCEPTED）**:
   - 通信回復時または手動更新時に、他端末・他担当者が作成・変更した最新の共有計画リストが自動的に取得・同期されます。
4. **物理実装の留保（CURRENT-PROPOSAL / PENDING）**:
   - 物理ストレージ技術（IndexedDB等）や更新ジェスチャー（Pull-to-Refresh等）の完全固定は行わず、実装Phaseで柔軟に選択します。

---

## 11. 未確定事項・検証課題（Pending Items）

- **`PENDING-C4-LIST-CLEANUP-TIMING`（飛行リストの自動整理・削除時点と条件）**:
  - 飛行完了後即時にリストから消すか、当日中は履歴として残すか、予定時刻経過後にどのタイミングで未着手計画を整理・アーカイブするかについて、99.2（Line 414）に基づき正式にPENDINGとして継続検討します。
- **`PENDING-C1-UI-PERMISSIONS`（権限とボタン活性条件の詳細マッピング）**:
  - 三層権限（業務役割・機能権限・Drive ACL）とボタン表示の対応ルールの確定。
- **`PENDING-C4-EXTERNAL-DIPS-IMPORT`（外部DIPS作成予定の取り込み）**:
  - アプリ外（国交省DIPS Web等）で直接作成された計画は、将来の同期/import機能がない限り本リストへ自動反映されない制約境界の扱い。
- **`PENDING-C4-LIST-SYNC-CONFLICT`（同一計画に対する現場二重着手の防止）**:
  - 同一計画を複数の操縦者が同時に開いて点検を開始しようとした場合の現場警告仕様。
