# 34e. 飛行履歴・出力

最終更新: 2026-09-19\
由来: 99.2 §8の飛行履歴・出力UIと出力選択（Step 7d）。34bが入口の意味までとした［飛行履歴・出力］の画面仕様を、10項目規約で記録する。\
主要責務: 過去の飛行の検索・選択と、必要な出力（KML・PDF）への導線。出力の内容・生成契機は[27e](../output/27e_kml-generation-timing-and-content.md)・[27f](../output/27f_derived-pdf-roles-and-map-pdf.md)、A4は[35c](../operation-recording/35c_a4-operation-record.md)\
規約: [30の10項目](30_screen-specification-standard.md)。

## 1. 入口から出力選択まで詰めた因果

**当初状態**: 34bは、ホームを2入口から3入口、4入口へ進めた際に、［飛行履歴・出力］を、完了済みの過去のFlightを検索・選択して正式記録を確認し、必要なPDF・KML等へ進む独立した入口とした。ただし検索条件・出力プレビュー等の詳細画面は対象外（PENDING-S5-HOME-DETAIL）だった。

**問題**: 過去の実飛行を探す目的は、これから扱う計画を選ぶ［飛行リスト］（[34c](34c_shared-flight-worklist.md)）とは別である。利用者に内部の`flight_id`を覚えさせず、人が読める条件で対象を選べる必要がある。また毎飛行でPDFを自動生成すると不要なファイルが増えるため、必要な出力だけを作る導線が要る（99.2 §8）。

**現在の到達点（CURRENT-ACCEPTED。99.2 §8）**: ホームの［飛行履歴・出力］から、日付、機体、場所や飛行名、目的、操縦者等の人が読める条件で対象の飛行を検索・選択する。内部の`flight_id`で、04の運航記録、06のDIPS通報内容・Geometry・証跡、07のKML・PDFを結び付ける。対象の飛行の詳細から、［My Maps用KML］［A4運航記録PDF］［地図付きPDF］等へ進む。

**出力選択（CURRENT-PROPOSAL）**: 不要なPDFの増殖を防ぐため、対象の飛行を選んだ後に、［A4運航記録PDF］［地図付きPDF］［両方作成］のように必要な出力を選ぶ方式を、99.2は第一候補とする。KMLも同じ飛行の詳細から扱う。第一候補であり、確定した仕様ではない。

## 2. 飛行履歴・出力画面の10項目

| 番号 | 記録項目 | 現在の内容・未確定 |
|---|---|---|
| 1 | 目的 | 完了済みの過去の飛行を、人が読める条件で探して選び、その飛行の正式記録に基づく出力へ進む |
| 2 | 入口・入れる条件 | ホームの［飛行履歴・出力］（34b）。環境の選択は[34a](34a_setup-and-environment-entry.md)、操作可否は31b。入れる条件の詳細は未確定 |
| 3 | 表示情報 | 検索・選択の条件（日付、機体、場所や飛行名、目的、操縦者等）。利用者に`flight_id`を見せない・覚えさせない。表示する項目の全一覧・結果の見せ方は未確定 |
| 4 | 初期値・自動入力 | 選択中の環境の04・06・07を参照する。初期の条件・並び順は未確定 |
| 5 | 主操作・副操作 | 条件で検索、対象の飛行の選択、飛行の詳細からの出力（［My Maps用KML］［A4運航記録PDF］［地図付きPDF］等）。出力を選ぶ方式は§1のCURRENT-PROPOSAL |
| 6 | 操作後の遷移 | 出力後の表示・共有・保存先の確認の遷移は未確定 |
| 7 | 戻る・中止・削除 | 詳細から検索へ戻る。生成の中止の扱いは未確定。記録の削除は本画面の責任にしない |
| 8 | 保存・更新時点 | 検索・詳細の表示は記録を更新しない。PDFは出力を選んだ時だけ07へ生成する（27f）。KMLは飛行計画の通報時に生成・保存済みで、ここで作り直さない（27e）。`flight_id`による結合はPENDING-S7B-FLIGHT-KEY（[24b](../dips-submission/24b_dips-plan-records-and-worklist-lifecycle.md)） |
| 9 | 権限・online/offline差 | 権限は[31b](../identity-and-access/31b_roles-and-access-control.md)と、環境のGoogle実アクセス。オフラインでは端末に取得済みのデータの範囲に限られ、端末でのPDF生成の条件は[18 §6](../18_reports.md#6-オフラインpdf生成の成立条件)、Drive・My Mapsへの保存や表示は通信が必要（[14](../14_offline-and-sync.md)）。cache鮮度の詳細は未確定 |
| 10 | 未確定 | §3の一覧 |

## 3. 未確定・確認待ちと適用限界

- **PENDING-S7D-HISTORY-DETAIL**: 検索条件の全項目・初期値・並び順、結果と詳細の表示、出力後の遷移、生成の中止、権限とoffline表現、出力選択の方式の確定。
- **PENDING-S7D-HISTORY-OUTPUT-UNIT**: 1つの飛行が、複数のA4シートや複数の機体のSpreadsheetにまたがる場合（7枠を超える場合や機体交代、[35c §3](../operation-recording/35c_a4-operation-record.md#3-その後の運用判断による現在ベースライン)）の、A4運航記録PDFの出力単位と、飛行から04の対象シートを特定する対応。割当は[35d](../operation-recording/35d_operation-finalization-and-write-boundary.md)のPENDING-S6-FINAL-SAVE-CONTRACTに従う。
- **PENDING-S7D-HISTORY-KML**: 履歴からKMLを取得する際の、保存済みKMLへの案内、未同期・未生成の場合の扱い、再生成の可否。
- 既存のまま維持: PENDING-S5-HOME-DETAIL（各種設定・管理の分類等。飛行履歴・出力の詳細は本書へ移した）、PENDING-S7B-FLIGHT-KEY。

本書は画面の記録であり、画面の実装・実機確認の完了ではない。旧資料（98.2の画面と保存先の整理）は今回再確認していない。
