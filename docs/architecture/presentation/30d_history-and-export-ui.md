## 1. 画面の目的（Purpose）

### 1.1 完了済み運航の閲覧・出力入口としての本質（CURRENT-ACCEPTED）

- ホーム画面の **③［飛行履歴・出力］** は、日々の運航・点検が完了した過去の飛行記録を検索・閲覧し、業務や行政提出に必要な各種帳票（PDF）や地理情報（KML）をオンデマンドで出力するための専門の入口です。
- 本画面は、作業中のタスクキューを扱う ②［飛行リスト］（[30c_shared-flight-list-ui.md](30c_shared-flight-list-ui.md)）とは明確に分離され、確定済み台帳（`04_運航記録` および `06_DIPS関連`）を参照元とし、外部出力領域（`07_出力_PDF・KML/`）へ派生成果物を生成・共有する役割を担います。
- **A4運航記録の原本性保護（CURRENT-ACCEPTED）**:
  - `04_運航記録` の日付シート（A4縦1枚・最大7明細、Step 6確定）が正式な正本データであり、PDFはそのオンデマンド派生出力です。
  - 本画面からのPDF出力操作において、A4運航記録へ点検整備サマリー等の異種データを混入させたり、Step 6で確定した元記録構造を変更することは禁止します。
- **KML出力の境界維持（CURRENT-ACCEPTED）**:
  - KMLは飛行計画通報時に確定内容（`submission_snapshot` ＋ 共通Geometry）から生成された派生物であり、事後運航実績は含まれません（[27a_kml-export.md](../output/27a_kml-export.md)）。本画面からは生成済みKMLの再取得・共有を扱います。

### 1.2 画面構成モデルの提案（NEW-PROPOSAL）

現場スマートフォンでの視認性と操作性を確保するため、本機能は以下の**2画面構成**（`NEW-PROPOSAL`）として整理します。

```text
┌─────────────────────────────────┐
│ SCR-HIST-01 飛行履歴一覧・検索   │ (過去フライトの検索・絞り込み・カード一覧)
└──────────────┬──────────────────┘
               │ タップ選択
               ▼
┌─────────────────────────────────┐
│ SCR-HIST-02 飛行詳細・出力画面   │ (飛行実績・点検結果の確認、PDF/KMLオンデマンド出力)
└─────────────────────────────────┘
```

※画面識別子 `SCR-HIST-01` / `SCR-HIST-02`、2画面分割構成、および後述の具体的UIレイアウトは、Step 7で具体化された提案（`NEW-PROPOSAL`）です。

## 2. 進入条件・前提状態（Entry Conditions）

- **進入経路（CURRENT-ACCEPTED）**:
  - ホーム画面の ③［飛行履歴・出力］ をタップすることで `SCR-HIST-01` へ進入する。
  - `SCR-HIST-01` の履歴カードをタップすることで、対象飛行の `SCR-HIST-02` へ進入する。
- **前提データ（CURRENT-ACCEPTED）**:
  - 運用環境の確定台帳（`04_運航記録` / `06_DIPS関連`）または端末ローカルキャッシュに、完了済み飛行記録が存在すること。
  - 履歴が存在しない場合は、空状態メッセージ「完了した飛行記録はありません」を表示する。

## 3. 表示情報（Displayed Information）

### 3.1 SCR-HIST-01: 履歴一覧・検索画面の表示要素（NEW-PROPOSAL）

1. **ヘッダー**: 画面タイトル「飛行履歴・出力」、［ホームへ戻る］ボタン。
2. **検索・絞り込みバー（NEW-PROPOSAL）**:
   - 人が読める条件による検索（日付範囲、機体、操縦者、場所/飛行名）（`CURRENT-PROPOSAL` - 99.2 §8 Line 488）。
   - クイック期間フィルター（［今月］［直近3ヶ月］［全期間］等）（`NEW-PROPOSAL`）。
3. **履歴カードリスト（NEW-PROPOSAL）**:
   各カードに以下のサマリーを表示：
   - 飛行実施日（例: `2026-09-20`）
   - 場所名称（例: `○○海岸 第1工区`）
   - 使用機体（例: `EVO Lite+ (JU3269B165D2)`）
   - 操縦者氏名
   - 総飛行回数・総飛行時間（例: `3フライト / 計45分`）
   - 外部保存同期ステータス（［同期完了］または［未同期あり］）

### 3.2 SCR-HIST-02: 飛行詳細・出力画面の表示要素（NEW-PROPOSAL）

1. **ヘッダー**: 画面タイトル「運航記録詳細」、［一覧へ戻る］ボタン。
2. **運航基本情報カード**: 日時、場所、飛行目的、操縦者、立会人/補助者、使用機体、使用バッテリー一覧。
3. **個別飛行実績テーブル**: 各フライトの離着陸時刻、実飛行時間（分）、使用バッテリー個体、特記事項。
4. **日常点検結果サマリー**: 飛行前点検判定（合格/不合格）、飛行後点検判定（合格/不合格）。
5. **DIPS通報・空域情報サマリー**: 計画番号、通報ステータス、許可承認番号。
6. **出力アクション領域（CURRENT-PROPOSAL / NEW-PROPOSAL）**:
   - ［A4運航記録 PDF出力］ボタン
   - ［地図付き飛行計画 PDF出力］ボタン
   - ［両方まとめて出力］ボタン
   - ［My Maps用 KML出力 / 共有］ボタン

## 4. 初期値／自動入力（Initial Values & Auto-fill）

- **検索初期状態（NEW-PROPOSAL）**:
  - 初期表示時は「直近30日間」の完了済みレコードを降順（新しい日付順）で自動表示する。
- **帳票出力オプション初期値（NEW-PROPOSAL）**:
  - 出力先フォルダーは、`07_出力_PDF・KML/` 配下の該当領域を自動設定し、ユーザーに手動選択を要求しない。

## 5. 主操作／副操作（Primary & Secondary Actions）

### 5.1 SCR-HIST-01（一覧画面）
- **主操作**: 履歴カードのタップ（対象の `SCR-HIST-02` 詳細画面へ遷移）。
- **副操作**: 検索条件の入力・クリア、期間フィルターの切り替え。

### 5.2 SCR-HIST-02（詳細画面）
- **主操作**: ［帳票・地図の出力］（出力選択モーダル起動、または各出力ボタン押下）。
- **副操作**:
  - ［Google Drive原本を開く］（Sheets実ファイルへの外部リンク）。
  - ［KMLを外部アプリで開く］（OS標準の共有シート呼び出し）。

## 7. 戻る／取消／削除の扱い（Back, Cancel, Delete Handling）

- **ヘッダーの「戻る」**:
  - `SCR-HIST-01` からはホーム画面へ戻る。
  - `SCR-HIST-02` からは `SCR-HIST-01` の同一検索条件・スクロール位置へ戻る。
- **出力モーダルのキャンセル**:
  - 生成処理を行わずにモーダルを閉じ、詳細画面の状態を維持する。
- **確定データの削除禁止（CURRENT-ACCEPTED）**:
  - 本画面は閲覧・出力専用であり、確定・同期済みの飛行日誌レコードをアプリ上から直接削除・破棄する操作は提供しません（法的証跡保護）。

---

## 8. 保存・更新対象と反映タイミング（Data Targets & Timing）

1. **データ読み込み（Data Reading）**:
   - 端末ローカルキャッシュ（IndexedDB）を優先表示し、通信可能時は `04_運航記録` および `06_DIPS関連` との差分をバックグラウンドで照会する。
2. **オンデマンド出力生成（On-demand Generation - CURRENT-ACCEPTED）**:
   - PDFファイルは自動生成せず、ユーザーが出力ボタンを押下した瞬間にオンデマンドで生成する（不要PDFファイルのDrive上での増殖防止 - 99.2 §8 Line 483）。
   - 生成されたPDFは、Google Driveの `07_出力_PDF・KML/PDF/`（※詳細サブ階層は `CURRENT-PROPOSAL`）へ保存され、ブラウザ内でダウンロードまたは印刷ダイアログが開く。
3. **物理ID・結合方式の保留（PENDING-C1-SCHEMA）**:
   - 利用者に内部IDを意識させず、内部キーによって `04_運航記録`、`06_DIPS関連`、`07_出力` を自動結合する方針は `CURRENT-PROPOSAL`（99.2 §8 Line 489）としますが、具体的な `mission_id` / `flight_id` 等の物理スキーマおよび外部キー結合仕様は **`PENDING-C1-SCHEMA`** として留保します。

## 10. Online / Offline 時の挙動差異（Connectivity Variations）

- **Offline時（現場・通信圏外）**:
  - 端末ローカルキャッシュに保存されている完了済み記録の閲覧は完全に可能。
  - PDFのブラウザ内即時レンダリング・印刷プレビューは端末ローカルエンジンにより実行可能。
  - Google DriveへのPDF自動保存ジョブは `SyncQueue` にキューイングされ、電波回復時に非同期保存される。
- **Online時（通信可能環境）**:
  - Google Drive原本との整合確認、およびPDFのDrive直接保存・共有リンク発行が即時完了する。
