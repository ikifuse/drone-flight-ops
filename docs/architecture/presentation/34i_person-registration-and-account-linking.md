# 34i. 人員登録・本人編集とGoogleアカウント欄

最終更新: 2026-09-24\
状態: 本人アカウント再入力の省略はCURRENT-ACCEPTED。画面全体の確定ではなく、その他は既存PENDINGを維持する。\
由来: 2026-09-24のオーナー指示と、動くモックの人員共通フォーム・自分の情報の確認。\
主要責務: 人員登録・編集での対象の識別、Googleアカウント欄の表示と保存への引継ぎ。人物・アカウントの意味と紐付け規則は[31a §6](../identity-and-access/31a_person-account-and-environment.md#6-個人本人の既知googleアカウントを再入力させない2026-09-24)、役割は[31c](../identity-and-access/31c_operational-actors.md)。

## 1. 発端・採用範囲と責任配置

**HISTORICAL**: 人員フォームは本人にも任意のGoogleアカウント欄を表示し、［自分の情報を使う］も基本情報の転記だけを行っていた。個人本人を登録するつもりでも別Personの追加になり、既知アカウントの再入力と人物の重複を招く構造だった。

**CURRENT-ACCEPTED**: 個人本人を対象にした登録・編集だけは、31a §6の既知アカウントを再入力させない。本人以外・会社／団体の人員フォームは従来の任意欄を保持する。画面数・認証導線・操縦者役割の成立条件は変更しない。

**Responsibility Check（6観点）**: 31aは人物とアカウントの概念・対応、31cは運航役割、34aは初回・本人情報・環境入口を担当する。人員共通フォームは、(1)本人以外・会社人員も対象とする別の主要責務を持ち、(2)初回導線と異なり登録後の継続的な人員編集というライフサイクルを持ち、(6)フォームの表示条件は概念モデルから独立して変わり得るため、本画面正本へ分ける。(3)外部依存、(4)セキュリティ境界、(5)実装Phaseは追加・変更しない。権限は31b、所属終了は31d、保存方式は既存正本へ委ねる。役割・認証・台帳の二重正本を作らない。

**ADR判断**: [ADR-0016](../../decisions/ADR-0016-environment-membership-and-access-separation.md)の人物・アカウント分離と[ADR-0030](../../decisions/ADR-0030-personal-first-onboarding-and-single-screen-initial-registration.md)の登録済み情報の再利用を具体化するUI変更であり、新ADRは不要。既存ADRの承認状態は変更しない。

## 2. 人員登録・編集の10項目（今回の限定範囲）

| 番号 | 記録項目 | 内容と境界 |
|---|---|---|
| 1 | 目的 | 人員を登録・編集する。個人本人については既知のGoogleアカウントを再入力せず紐付けを維持する |
| 2 | 入口・入れる条件 | ［各種設定・管理］の人員一覧、または新規飛行等の途中登録（34a §9.8）。本人の選択は現在環境の本人Personへの対応を使う。氏名一致で決めない |
| 3 | 表示情報 | 個人本人はGoogleアカウント入力欄を非表示。他人・会社／団体の人員は「Googleアカウント（任意）」を表示。氏名・連絡先・役割等の全項目や配置の確定は今回の範囲外 |
| 4 | 初期値・自動入力 | 個人本人の登録・編集下書きに既知アカウントを自動紐付けする。連絡用メールとは分離。操縦者役割は認証から付与しない |
| 5 | 主操作・副操作 | 保存・キャンセル。モックの個人人員追加では［自分を登録する］で既存の本人Personを対象に切り替える。既存の本人情報・役割・資格と呼出元で選ばれた役割の既定値を引き継ぎ、重複Personを作らない。他人の編集・会社の［自分の情報を使う］は従来の基本情報転記のままで、本人への対象切替・自動紐付けを行わない |
| 6 | 操作後の遷移 | 設定からは元の人員一覧へ、途中登録からは元の操作へ戻り同じPersonを渡す。独立した完了画面は作らない |
| 7 | 戻る・中止・削除 | キャンセルでは登録・編集下書きを保存しない。今回、人物削除・離任・再所属の仕様は変更しない（31d） |
| 8 | 保存・更新時点 | 保存時に対象Personの対応を維持する。モックは開いた時点では下書きだけを初期化し、保存でメモリー内の人員へ反映する。Drive等への物理保存契約は未決のまま |
| 9 | 権限・online/offline差 | 31bの三層権限を維持。本人であることから新しい権限を付与しない。本番の認証失効・offline保存・再認証の詳細は未決。既知アカウントがない場合に手入力で認証済み対応を捏造しない |
| 10 | 未確定 | PENDING-S2-IDENTITY、PENDING-S2-MEMBERSHIP、PENDING-S2-ACCESS-DETAIL、PENDING-D-SETTINGS-SCREENS等の残り。今回確定した本人のアカウント欄と紐付けだけを区別し、全体解消と扱わない |

## 3. ［自分の情報］との接続と検証範囲

［自分の情報］は[34a §9.9](34a_setup-and-environment-entry.md#99-個人本人の登録編集でgoogleアカウントを再入力しない2026-09-24)の経路で同じ本人を編集する。個人本人の編集下書きには同じ既知アカウントを初期化し、保存で紐付けを維持する。Googleアカウントの入力欄は置かず、既存の連絡用メール欄を認証アカウント欄に転用しない。会社・団体の［自分の情報］の既存項目・アカウント利用は変更しない。

**EVIDENCE/EXAMPLE**: モックの`reg-person`と`set-me`で登録・編集・保存・取消、他人・会社／団体の任意欄、操縦者初期選択との接続を検査する。[回帰テスト](../../../design-mock/app/tests/t2_settings_registration.js)・[モックREADME](../../../design-mock/app/README.md)へ実行結果を記録する。本番認証・実機・外部保存を確認した意味ではなく、C1は未着手。
