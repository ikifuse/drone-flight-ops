## 1. 地図・空域データのレイヤー構造

本システムでは、描画・計算・判定の独立性を担保するため、地図および空域規制データを以下の5つの独立レイヤーとして階層管理します。

```text
┌─────────────────────────────────────────────────────────────┐
│ [レイヤー5: 飛行範囲レイヤー (FlightArea)]                  │
│  - パイロットが描画した円（中心＋半径）または多角形ポリゴン│
├─────────────────────────────────────────────────────────────┤
│ [レイヤー4: 周辺飛行計画レイヤー (Surrounding Plans)]       │
│  - DIPSから取得した他機の飛行計画表示                       │
├─────────────────────────────────────────────────────────────┤
│ [レイヤー3: 航空法規制空域レイヤー (Regulated Airspace)]    │
│  - 空港等周辺空域、進入表面、緊急用務空域                   │
├─────────────────────────────────────────────────────────────┤
│ [レイヤー2: 人口集中地区レイヤー (DID)]                     │
│  - 国勢調査DID境界ポリゴン                                  │
├─────────────────────────────────────────────────────────────┤
│ [レイヤー1: 地図背景タイル (Base Map Tiles)]                │
│  - 国土地理院タイル（標準地図 / 淡色地図 / 航空写真）      │
└─────────────────────────────────────────────────────────────┘
```

## 2. 飛行範囲（FlightArea）の内部標準データモデル

パイロットが現場で直感的に操作でき、かつDIPS通報仕様にも適合するハイブリッド表現を採用します。

### 2.1 データ定義
```typescript
export interface FlightArea {
  flight_area_id: string;      // UUID v4
  name: string;                // 現場名（例: "〇〇海岸フライト"）
  shape_type: 'circle' | 'polygon';
  
  // 円形指定時
  center?: {
    latitude: number;          // 10進（例: 35.6895）
    longitude: number;         // 10進（例: 139.6917）
    radius_meters: number;     // 半径（m）
  };

  // 多角形ポリゴン指定時
  polygon_coordinates?: [number, number][]; // [ [lng, lat], [lng, lat], ... ]

  // 高度属性（150mは航空法規制閾値であり、既定計画高度ではない）
  planned_altitude_agl_meters: number; // 計画対地高度（m、実飛行計画値）
  max_altitude_agl_meters: number;     // 運用上限対地高度（m、安全マージン含む）
  planned_altitude_msl_meters?: number; // 計画海抜高度（m、任意）
  altitude_source: 'manual_input' | 'dem_elevation' | 'dips_imported';

  geojson: GeoJSON.Feature;        // 標準GeoJSON表現（自動生成保持）
  
  created_at: string;
  updated_at: string;
}
```

### 2.2 操作機能
- **円描画モード**: 地図上をタップして中心点を決め、半径（m）を直感指定。
- **ポリゴン描画モード**: 頂点をタップして順次追加。
- **過去範囲の再利用・複製**: 過去の飛行実績からワンタップで同一エリアを呼び出し、再計画へ適用。

## 3. 空域データソースの確認状況とライセンス・キャッシュ条件

データソースの法的位置づけ、利用規約、オフライン再配布条件を以下の3区分で厳格に整理します。

| レイヤー | データ提供元 | 確認区分 | 利用規約・キャッシュ条件 | 更新頻度 |
|---|---|:---:|---|---|
| **国土地理院タイル** | 国土交通省 国土地理院 | **【確認済み】** | 国土地理院コンテンツ利用規約に準拠（出典明記で無償利用可）。ブラウザ通常キャッシュは可。**※大量タイルの一括スクレイピング・オフライン再配布はサーバー負荷軽減規約により制限**されるため、実現場周辺のブラウザ自動キャッシュを基本とする。 | 定期更新 |
| **DID（人口集中地区）** | e-Stat / 国土数値情報 | **【確認済み】** | 国土数値情報（令和2年国勢調査）GISデータ。オープンデータ利用可。GeoJSON化して軽量配信・事前キャッシュ可能。 | 5年ごと |
| **空港等周辺空域** | 国交省航空局オープンデータ / G空間情報センター | **【候補】** | 空港制限表面データ。GISデータからのGeoJSON変換・配信を検討。境界付近の誤差検証が必要。 | 航空路誌（AIP）改訂時 |
| **進入表面・転移表面等の精密3D空域** | 国交省 / 空港設置管理者 | **【未確認】** | 全国分の精密な3次元表面データをGeoJSON等で無償一括取得・アプリ同梱できる公式APIの有無は未確認。 | 不定期 |
| **緊急用務空域** | 国交省航空局告示 | **【未確認】** | 災害・事故発生時に随時告示。公式な常時REST APIの提供は未確認であり、通信接続時の告示情報取得またはDIPS Web確認を前提とする。オフライン時は「未確認」と明記。 | 都度告示 |

## 4. 空域表示を「飛行可否判定」と誤認させないUI設計原則

アプリ上の地図レイヤーおよび規制空域表示は、**操縦者の状況把握を補助するための安全支援情報**であり、法的な飛行許可や飛行可否を絶対判定するものではありません。国交省も、空港周辺等の境界付近では管轄機関や空港設置管理者への個別確認を案内しています。

```text
┌─────────────────────────────────────────────────────────────┐
│ 【空域・飛行計画確認UIの表示原則】                          │
│                                                             │
│  [!] 規制空域の重なりなし                                   │
│  情報源: 国土数値情報 (DID: 2020年版) / 航空局公開データ    │
│  データ最終更新: 2026-04-01 | 通信状態: オフライン(キャッシュ) │
│                                                             │
│  ※本表示は安全確認の補助情報です。境界付近の飛行可否判定を │
│    保証するものではありません。必要に応じて空港事務所・     │
│    施設管理者およびDIPS 2.0本番画面をご確認ください。       │
└─────────────────────────────────────────────────────────────┘
```

1. **「飛行可能」という断定表示の禁止**:
   - 規制空域外であっても「飛行可能！」「GO」等の安易な断定ラベルは配置せず、「既知の規制空域との重複は検出されませんでした（要最終目視確認）」という慎重な表現を徹底。
2. **鮮度・情報源の常時明示**:
   - データ最終更新日時、情報源、現在オフラインか否か、未取得レイヤーの有無を画面上に明記。
3. **境界マージンと注意喚起**:
   - 空港周辺やDIDの境界線から一定距離（例: 1km以内）にある場合は、「境界接近中: 管理機関への確認を推奨」と注意喚起。
