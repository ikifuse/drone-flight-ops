# 32g. BAT使用開始・交換時の現場入力（4項目）と自動記録

最終更新: 2026-09-20\

## 1. 本書の位置づけ

現場でBATを扱うたびに人へ求める入力を、必要最小限に絞った理由と内容を保持する。BAT管理がOFFの機体（32e）では、この入力を求めない。選択の候補は、対象機体に使用が許可されたBATだけ（[32h §8](32h_registered-aircraft-and-battery-group-relations.md#8-飛行時のbat選択候補案)）。BATの取得時の確認は[32b §3](32b_battery-sharing-and-acquisition-history.md#3-中古batの取得時確認とその後の履歴)、画面の10項目は35b §7が正本で、本書は複写しない。

## 2. 入力を4項目に絞った因果

**当初状態**: 統合要件は、飛行ごとの使用BAT個体の必須記録、飛行前後の残量、サイクル数（確認できた場合に任意）、所感・異常メモ、交換時の残量・温度・警告表示の最小の確認（3ステップ）を置いていた（[03 §2.2・§2.3](../../03_integrated-requirements.md)）。

**問題**: BATを交換するたびに多くの項目を求めると、現場（手袋・屋外・片手。[00_goal §3](../../00_goal.md)）で操作の負担が大きく、入力忘れや確認忘れが起きる。特にサイクル数は、機体やアプリ等から毎回調べる運用を必須にすると、確認忘れと操作負担が大きい。

**現在の到達点（CURRENT-ACCEPTED）**: BAT管理がONの機体で、BATの使用開始・交換時に人が扱う項目は、次の4項目までに絞る。

| 項目 | 必須／任意 | 意味・理由 |
|---|---|---|
| 管理ラベル | 必須 | システムIDではなく、利用者がテプラ等で実物のBATにも貼り、現場で「BAT 1」「BAT ⑤」のように即座に識別するための、人間向けの識別名 |
| サイクル数 | 任意 | 確認した時だけ実測値を入力する。未確認でも飛行を止めない。使用回数からサイクル数を推定して自動で加算しない |
| 状態確認 | 必須 | 交換時にBATを実際に手に取るので確認できるため。選択肢は§4 |
| 備考 | 任意 | 自由記入。セル電圧等の高度なBAT内部の管理は専用の必須項目にせず、必要な利用者は備考へ記録できる程度にとどめる |

管理ラベルは、内部のID（`battery_id`。UUID）とは別の、人が読む名前である（12bの`display_name`に近い。対応は32f §4の目安）。

## 3. 自動で記録・集計する値（CURRENT-ACCEPTED）

使用日時、実際に使用した機体、今回の飛行時間、当方の管理開始後の累計飛行時間、使用回数、最終使用日など、アプリ自身が知ることができる値は、原則として人に再入力させない。飛行の記録から、自動で記録・集計する。保存先の列は32fの候補で、確定していない。

## 4. 状態確認の候補（CURRENT-PROPOSAL）

現在の候補は「異常なし」「膨らみあり」「異常な発熱あり」等。次は未確定である。

- **PENDING-D-BAT-CHECK-UI**: 選択肢の一覧、単一選択か複数の異常の選択か、「その他の異常」を設けるか、UIと保存の形。異常が選ばれた場合に、画面で警告するか、使用停止を促すか（離陸前の総合評価は安全支援であり、実際に発生した離陸の記録は拒否しない。[13c](../state-machines/13c_takeoff-readiness.md)）。

## 5. 既存の要件との関係

統合要件の§2.2の飛行前後の残量（%）と、§2.3の交換時の残量・温度・警告表示の最小の確認は、現在の4項目に含まれない。これらを、着陸後入力や飛行前点検など別の場面で残すか、なくすかは未確定である（PENDING-D-BAT-LEGACY-CHECKS）。既存の要件は、この判断まで削除しない。

## 6. 未確定と再検討条件

- **PENDING-D-BAT-LABEL-RULE**: 管理ラベルの一意性の範囲（機体系の中で一意か）、命名の決め方、変更・重複した場合の扱い。
- **PENDING-D-BAT-CYCLE-DISPLAY**: 最新サイクル数が未確認または古い場合の見せ方（最終確認日の表示など）。
- **PENDING-D-BAT-LEGACY-CHECKS**: §5の扱い。
- 既存のまま維持: PENDING-D-BAT-CHECK-UI（§4）、PENDING-S6-OPERATION-UI（35b）、PENDING-C1-SCHEMA。

**再検討条件**: 4項目では安全・保全に足りないと実運用で分かった場合、逆に4項目でも現場の負担が大きい場合、オーナーが必須／任意を変える場合。
