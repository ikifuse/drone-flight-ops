# ADR-0024: KMLは飛行計画通報時に通報内容と共通Geometryから生成し、運航実績を含めない

- **作成日**: 2026-09-19
- **ステータス**: Proposed（未承認）。現在ベースラインの判断記録であり、ADR自体は未承認
- **関係性**: [ADR-0008](ADR-0008-user-facing-export-and-recovery-boundaries.md)のKMLは派生出力でDB復旧の代替にしないという決定と、[ADR-0023](ADR-0023-common-source-and-derived-submission-paths.md)の共通の源をClarifiesし、KMLの生成契機・内容・単位を加える。旧27a・27b・03・23のKML運航実績追記案（ADRに記録されていない設計文書の記述）を現在ベースライン上で置き換える。Accepted ADRの本文は変更しない
- **決定者**: 99.2 §8の現在到達点を、オーナーのStep 7c指示に基づきClaudeが記録
- **詳細正本**: [27e](../architecture/output/27e_kml-generation-timing-and-content.md)。形式・命名・共有プロファイルは[27a](../architecture/output/27a_kml-export.md)、移管と確認範囲は[Step 7c監査](../migration/99-2-step-7c-causal-audit.md)

## 1. 背景と課題（Context）

DIPS用に作った飛行範囲を、KMLやMy Maps・Google Earth等の地図で再入力せずに使いたい。旧設計は、計画確定時にKMLを作り、運航完了後に飛行前後の点検・各飛行の実績を追記して更新する「1 FlightPlan = 1 KML」とし、日時・操縦者・機体・目的等は候補として列挙して最終的な属性一覧は今後確定するとしていた。KMLは派生出力であり、飛行記録の正本でも正式なDIPS証拠でもない。

## 2. 検討した選択肢（Options Considered）

- A. 運航完了時に実績を追記して更新する（旧案）。
- B. KMLへ広い運航属性を載せ、属性一覧を後で確定する（旧案）。
- C. KMLだけの独自の属性一覧を別途選び直す。
- D. 飛行計画を確定してDIPSへ通報する段階で、通報内容と共通Geometryから生成し、運航後の情報を含めない。

## 3. 決定内容（Decision）

Dを現在ベースライン（CURRENT-ACCEPTED）として27eに記録する。

- KMLの内容は、DIPSへ通報する内容と、その通報対象の共通Geometryとする。運航後の情報は含めず、行政側の受付・計画番号等は06へ別に保持する。
- 生成と通常の保存は、飛行計画を通報する段階で行う。保存だけが失敗したKMLは端末に未同期として保持し、飛行後点検後の最後の送信時にも再送する。保存済みのKMLは重複して保存しない。
- 単位は、柔軟な運用上の1飛行につき1つの独立したKMLとする。

## 4. 採用理由と他案の却下理由（Rationale）

AとBは、KMLの内容の源が通報内容と共通Geometryで確定しており、後発の運航データを待たず、後から実績を追記する前提にしないため採らない。Bの保留表現は、99.2が現在の決定と矛盾する古い表現と明記している。Cは、内容が通報内容そのものを基準に確定しているため、KMLだけの独自の属性を選び直さない。

## 5. メリット（Pros）

- KMLの生成が運航の進行や実績に依存せず、通報時点で内容が一意に決まる。
- KML・Driveの障害が、DIPS通報・現場の離着陸・運航確定を止めない。
- 内容の基準が通報内容に一本化され、属性の再選定が不要になる。

## 6. デメリット・トレードオフ（Cons / Trade-offs）

- 運航実績はKMLでは確認できない。実績の可視化は別の出力・将来の機体ログ重畳で扱う。
- 「提出項目を同じ意味内容として保持する」ことと、共有時に氏名・連絡先・登録記号を無条件に出さない既存のプロファイルの合成は未確定（PENDING-S7C-KML-SHARE-PROJECTION）。
- 意味上の1飛行と計画・改訂・複数日・複数機体・複数Missionの対応、DIPS対象外の飛行のKML、保存先の指定方法、最後の送信との契約は未確定。

## 7. 将来この決定を見直す条件（Re-evaluation Triggers）

- 運航実績を地図上で確認する必要が現場で実証された場合。
- My Mapsの実機検証で、通報内容の表現や再インポートの挙動が運用に合わないと確認された場合。
- 意味上の1飛行の定義が確定し、計画とKMLの対応が変わる場合。

本ADRは実装開始・Drive操作の許可ではない。
