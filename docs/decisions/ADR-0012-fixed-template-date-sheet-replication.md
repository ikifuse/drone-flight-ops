# ADR-0012: 統合帳票における固定1枚テンプレート日付複製方式の採用

- **作成日**: 2026-09-18
- **ステータス**: **提案中（Proposed）**
- **決定者**: 検討中（99.2設計検討正本反映 / オーナー最終監査待ち）
- **関連設計**: [18 帳票出力・監査](../architecture/18_reports.md)、[29 Drive物理階層・ストレージ設計](../architecture/drive-storage-schema/29_drive-folder-and-sheets-structure.md)
- **関連ADR**: [ADR-0007](ADR-0007-normalized-masters-and-business-reporting.md)、[ADR-0008](ADR-0008-user-facing-export-and-recovery-boundaries.md)

## 1. 背景と課題（Context）

国土交通省令に基づく日常点検記録および飛行記録は、現場での確認および行政監査への提示のため、A4縦（portrait）1枚に収まる印刷レイアウトの安定性が実用上重視されます。
従来の検討（ADR-0007等）では、1日の飛行回数が増加した際に「動的改ページ（Page 2, 3の動的生成）」や「フォントサイズ・行高の動的縮小」によって単一シート内へ収容する案が検討されていました。
しかし、スプレッドシート上での動的な行挿入やフォント縮小は、印刷マージンやヘッダー配置のズレを招きやすく、出力時のレイアウトの安定性を損なう懸念が指摘されました。

## 2. 検討した選択肢（Options Considered）

- **選択肢A: 動的改ページ・行追加方式（ADR-0007初期検討案）**
  明細行が増えるごとにスプレッドシートの行を動的に増やし、改ページを制御する案。印刷範囲や余白設定の崩れが生じやすい。
- **選択肢B: フォント・行高の縮小方式**
  行数に応じて文字サイズや行間を小さくして1ページに詰め込む案。文字の視読性が低下しやすい。
- **選択肢C: 固定A4縦1枚テンプレートの日付複製シート方式（推奨案）**
  手作業で調整された実物「固定A4縦1枚テンプレート（明細最大7行）」を基準とし、明細行上限（7行）を超過した場合等に、同一テンプレートを日付連番シート（`YYYY.M.D`, `YYYY.M.D_2`...）として複製（物理分割）する方式。

## 3. 決定内容（Decision）

選択肢Cを Proposed として起票します。

1. **固定A4縦1枚テンプレートの採用**:
   - 日常点検および飛行記録を1枚に集約した統合帳票テンプレートを採用し、1シートあたりの最大飛行明細行数を「7行」とする。
2. **日付複製シート（物理分割）の発行基準**:
   - 同一日の飛行明細が7行を超過した場合は、既存シートへの無理な行追加やフォント縮小を行わず、同日連番の新しいA4複製シート（`YYYY.M.D_2`, `YYYY.M.D_3`...）を発行して記録を継続する。
   - ※機体交代時や飛行場所切替時における新シート発行の要否・運用条件については、Domain層のFlight定義（同一Flightとするか別Flightとするか）との接続を含め、Step 6において詳細を検証・確定する（PENDING）。
3. **印刷整合性の確保**:
   - 各シートを完成されたA4縦1枚の独立した記録として扱うことで、改ページ設定や印刷範囲の崩れを抑制する。

## 4. メリット（Pros）

- 印刷レイアウトが固定され、印刷・PDF出力時の表示崩れリスクを大幅に低減できる。
- シート単位で点検結果と該当飛行明細の対応関係が明確になり、目視確認が容易になる。

## 5. デメリット・トレードオフ（Cons / Trade-offs）

- 1日に多数のフライトを行う場合、スプレッドシート内のシート数（タブ数）が増加する。
- 過去の運航記録を検索・集計する際、複数シートを横断して読み込むロジックが必要となる（正規化台帳側の管理と役割分担する）。

## 6. 今後の検証・昇格条件（Validation Criteria）

Step 6（Drive Storage Schemaおよび帳票設計更新）において、99.2 §5を主根拠とし、必要に応じて§6（点検整備記録）および§10（Drive新旧構造）との整合性を検証したうえで、Step 8の監査を経てAccepted候補としてオーナーへ提示し、オーナーの明示承認を受けて初めてAcceptedへ変更する。
