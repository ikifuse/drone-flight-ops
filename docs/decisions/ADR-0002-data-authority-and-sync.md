# ADR-0002: ライフサイクル連動型ハイブリッド正本モデルと手動修正尊重の採用

- **作成日**: 2026-09-14
- **ステータス**: **提案中（オーナーレビュー待ち）**
- **決定者**: オーナー（システム設計者）、AIアシスタント（技術検討パートナー）
- **関連ドキュメント**: [docs/architecture/11_data-authority.md](../architecture/11_data-authority.md), [docs/architecture/14_offline-and-sync.md](../architecture/14_offline-and-sync.md)

---

## 1. 背景と課題（Context）

新アプリ `drone-flight-ops` において、通信圏外の現場スマートフォンで記録されるデータ（IndexedDB）と、クラウド上のGoogleスプレッドシートのどちらを「正本（Single Source of Truth: SSoT）」とするかが大きな論点となっていた。
- 端末側を唯一の正本とすると、人間がスプレッドシート側で直接行う「手動補記・修正」を端末からの同期で上書き破壊してしまうリスクがある。
- スプレッドシートを唯一の正本とすると、山間部などの電波圏外で現場運航記録が中断・機能不全に陥るリスクがある。
- 現行アプリ（`autel-evo-lite-flight-log`）の最大の実運用価値である「現場での即時入力」と「スプレッドシート上での人間による手修正・監査の透明性」を両立するアーキテクチャが必要であった。

---

## 2. 検討した選択肢（Options Considered）

- **選択肢A: ローカルDB正本モデル**: 端末IndexedDBを唯一のマスターとし、スプレッドシートは出力先とする。
- **選択肢B: スプレッドシート正式原本モデル**: スプレッドシートをマスターとし、端末は一時キューとする。
- **選択肢C: クラウドDB正本モデル**: Supabase等のクラウドDBをマスターとし、端末とシートへ同期する。
- **選択肢D: ライフサイクル連動型ハイブリッドモデル（推奨案）**: 現場運航中は端末ローカルが一次権威、外部同期後はスプレッドシートが確定台帳となり、人間による手修正を過去データで上書きしない。

---

## 3. 決定内容（Decision）

**選択肢D（ライフサイクル連動型ハイブリッドモデル）** を採用することを決定した。

1. **現場運航中**: 端末内IndexedDBを「一次権威（Active Authority）」とし、ミリ秒打刻・オフライン自律稼働を担保する。
2. **外部同期後**: Googleスプレッドシートを「確定原本・台帳権威（Ledger Authority）」とする。
3. **手動修正の絶対尊重**: パイロットがスプレッドシートを直接編集した場合、過去の端末データで上書きすることは絶対に行わず、以後の機体累計時間・バッテリーサイクル計算は手動修正後の値を基点として継続する。
4. **競合検出**: 端末データとスプレッドシートの差分を検知し、衝突時はサイレント上書きをせず人間確認UIを提供する。

---

## 4. 影響と評価（Consequences）

- **メリット**:
  - 完全電波圏外でも1ミリ秒の通信待ちもなく現場記録を完結できる。
  - 現行アプリの「人間が直接見て直せる」「手修正しても計算が壊れない」安心感が完全に維持される。
  - 端末故障時でもスプレッドシートから最新台帳状態を引き継ぐことができる。
- **デメリット・留意点**:
  - 同期キューおよび競合検出（手動修正フラグやハッシュ照合）の実装ロジックが必要となる（Phase B2にて詳細設計済）。
