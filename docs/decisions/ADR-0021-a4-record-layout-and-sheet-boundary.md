# ADR-0021: 最新A4実物と固定明細シートによる運航記録

- **作成日**: 2026-09-18
- **追補日**: 2026-09-19（機体個体別保存・同日連番と特殊競合の非採用判断）
- **ステータス**: Proposed（未承認）
- **関係性**: Partially Supersedes ADR-0007 §2.9の点検整備サマリー・自動続紙・旧固定区切り解釈を現在ベースライン上で限定置換。§2.8の媒体例外は0022。Accepted本文は保持。
- **決定者**: オーナーの現在99.2 §5・§10、Step 6追加指示、および2026-09-19の追補判断を区別して記録。
- **関連要件・詳細正本**: [35c](../architecture/operation-recording/35c_a4-operation-record.md)、技術責任は[18](../architecture/18_reports.md)

## 1. 背景と課題（Context）

旧GASの横長No.1／No.2を離れ、旧18は縦A4の三領域・可変続紙を提案した。その後、人が直接読む実物をオーナーが手作業で整え、現在99.2に固定7枠と日付連番物理シートの運用判断が残った。旧18だけを現行とすると、存在しない整備サマリーを足すことになる。

追補ではオーナーが04の機体個体別Spreadsheetを実物確認結果として提示した。Step 6初版の機体交代と同一ファイル内の次連番を一括した解釈を補正する。証拠の主体と詳細因果は[35c §3.1〜§3.3](../architecture/operation-recording/35c_a4-operation-record.md#31-機体個体別の保存先を確認したことによる補正)に一元化する。同じA4保存判断の具体化であり、新ADRを増やさず本ADRをProposedのまま追補する。

## 2. 検討した選択肢（Options Considered）

- 旧左右2運航の物理枠をそのまま採用。
- 旧18の三領域・可変行数・Page 2以降を維持。
- 最新実物の縦1枚と、99.2の後続運用判断を区別して採用。

追補で比較したのは、既存の機体別境界内で日付・次空き連番を使う案と、特殊なほぼ同時保存に備えて新識別子・操縦者コード付き名・中央採番・高度な排他／分散ロックを追加する案である。

## 3. 決定内容（Decision）

三つ目を現在ベースラインとして35cへ記録する。実Driveの直接確認はEVIDENCE/EXAMPLE、そこから現在設計として採用する意味と、1枚だけでは確認できない後続運用を別々に出典化する。実物の全文・寸法表をADRへ複製しない。

追補のCURRENT-ACCEPTEDは、対象機体Spreadsheet内の`YY.M.D`・同日次空き連番、機体交代時の保存先切替、特殊同時競合だけを理由とする高度な対策の意図的非採用。新しいID体系を追加しない。命名・競合条件・再検討条件の詳細正本は35c、通常再送の重複防止責任は[35d](../architecture/operation-recording/35d_operation-finalization-and-write-boundary.md)に維持する。

## 4. 採用理由と他案の却下理由（Rationale）

人間が整えた前後点検の比較配置と印刷の見通しを維持し、枠超過で文字を縮めない。旧横帳票の形や、実物にない整備サマリーは引き継がない。内部正規化と3層Report Modelは現行媒体と両立するため維持する。

別機体の通常運航は別ファイルへ保存される。同一機体の未同期受渡しと遅延同期・次運航保存の重なりは、オーナーが通常利用では非常に限定的と判断した条件であり、測定済みの発生率ではない。この特殊ケースだけのために通常設計を複雑化せず、既存名を避ける簡素な方式を選ぶ。

## 5. メリット（Pros）

原本、分割記録、印刷物の関係を人が辿りやすくし、最新実物と設計判断の証拠を取り違えない。

## 6. デメリット・トレードオフ（Cons / Trade-offs）

通常の命名方針は追補で具体化したが、複製・長期分割・再送割当は詳細契約が必要。次空き名の確認はほぼ同時の選択を完全に排他する保証ではない。汎用PDF取得APIとA4設定の差は35cのVERIFYへ残し、実紙印刷の成功を未確認で保証しない。

## 7. 将来この決定を見直す条件（Re-evaluation Triggers）

実物改訂、入力長・複数補助者の検証、長期保存要件の変更時。現行A4の採用とADR承認を分け、過去のAccepted本文の承認履歴を上書きしない。

追補した競合判断は、未同期受渡しの頻発、同一機体への並行保存競合、複数拠点での短時間受渡しの常態化、次空き連番では復旧できない事象が実証された場合に見直す。判定の詳細は[35c §3.3](../architecture/operation-recording/35c_a4-operation-record.md#33-特殊な同時競合を検討したうえで簡素な方式を選ぶ理由)。
