# ADR-0014: DIPS外部通信における専用固定送信元IPゲートウェイ方式の採用

- **作成日**: 2026-09-18
- **ステータス**: **提案中（Proposed）**
- **決定者**: 検討中（99.2設計検討正本反映 / オーナー最終監査待ち）
- **関連設計**: [15 DIPS連携アダプター](../architecture/15_dips-adapter.md)、[16 セキュリティ・秘密情報](../architecture/16_security.md)、[新設予定: dips-infrastructure](../architecture/dips-infrastructure/README.md)
- **関連ADR**: [ADR-0001](ADR-0001-architecture-selection.md)、[ADR-0004](ADR-0004-dips-adapter-architecture.md)

## 1. 背景と課題（Context）

国土交通省のDIPS 2.0 API連携においては、利用申請手続きおよびシステム接続要件として「接続元（送信元）のグローバル固定IPアドレスの事前登録」が確認されています。
初期アーキテクチャ（ADR-0001, ADR-0004）では、BFFプロキシとして「Cloudflare Workers」を採用し、トークン隠蔽やリクエスト中継を行う構成を採っていました。
しかし、一般的なサーバーレスエッジ環境（Cloudflare Workersの標準構成等）では送信元IPアドレスが動的に変動するため、国交省APIゲートウェイの接続要件を満たすことが困難となります。
これに対し、エッジワーカーからのダイレクト通信を前提としたままでは、Phase C7におけるAPI正式接続を実現できないというインフラ制約が存在します。

## 2. 検討した選択肢（Options Considered）

- **選択肢A: Cloudflare Workersからの直接API呼び出し（動的IP）**
  従来の初期想定構成。送信元IPが固定されないため、国交省APIの利用申請要件を満たせない。
- **選択肢B: Google Cloud NAT経由の専用固定送信元IPゲートウェイ構成（推奨案）**
  Google Cloudインフラ上でCloud NATおよび静的外部IPアドレスを確保し、API中継プロキシ（BFF）として機能させる方式。固定送信元IPからの通信経路を確立する。

## 3. 決定内容（Decision）

選択肢Bを Proposed として起票します。

1. **専用固定送信元IPゲートウェイの採用**:
   - 国交省DIPS APIとの通信インターフェースとして、Google Cloud NATを経由した固定グローバルIPアドレスを持つゲートウェイ構成を採用する。
2. **公開リポジトリにおける機微情報の秘匿**:
   - 実際の固定IPアドレス（数値実値）、GCPプロジェクトID、接続認証シークレット等は、本リポジトリ（公開設計書・コード）には一切記述せず、非公開の環境変数およびセキュアなシークレット管理に留める。
3. **Phase C6（手動通報支援）の独立性維持**:
   - 本固定IPインフラは、Phase C7のOptionalなAPI自動連携時にのみ必要とされる基盤であり、Phase C6の手動通報支援および現場運航管理は、このAPI通信インフラから完全に独立して成立する。

## 4. メリット（Pros）

- 国土交通省DIPS APIの公式接続要件（固定送信元IP）に対応可能な通信経路を確保できる。
- API通信のインフラ責務が専用ゲートウェイ内に局所化され、クライアントアプリ（PWA）のコードを一切汚染しない。
- 手動通報支援（Manual）とAPI自動通報が疎結合となり、APIインフラの準備状況に依存せず現場運航業務を構築できる。

## 5. デメリット・トレードオフ（Cons / Trade-offs）

- Cloudflare Workers単体構成に比べ、Google Cloud側のネットワークインフラ（Cloud NAT、静的IP予約）の設定・管理が必要となる。
- 静的IPアドレスの維持費やNATトラフィック課金等のインフラコストが発生するため、実機検証段階で試算・監視が必要となる。

## 6. 今後の検証・昇格条件（Validation Criteria）

Step 4（DIPSインフラ基盤設計および空域モデル整合）において、99.2 §7の記述および国交省申請実務との整合性を検証し、Step 8の監査を経てAccepted候補としてオーナーへ提示し、オーナーの明示承認を受けて初めてAcceptedへ変更する。
