# ADR-0017: 機材取得履歴・管理累計の意味と点検整備Actorを分ける

- **作成日**: 2026-09-18
- **ステータス**: 提案中（Proposed）。CURRENT-ACCEPTEDとADR承認は別
- **関係性**: Clarifies [ADR-0007 §2.1・§2.2](ADR-0007-normalized-masters-and-business-reporting.md)の型式／個体・共有機材モデル、および[ADR-0002](ADR-0002-data-authority-and-sync.md)の累計基点の意味。既存ADRの承認履歴・本文を変更せず、承認済み決定を正式に置換したという記録ではない
- **決定者**: 99.2に記録された現在到達点を、オーナーのStep 3指示に基づきCodexが記録。ADR自体は未承認
- **関連要件**: [統合要件](../03_integrated-requirements.md)、99.2 §4と取得確認・Actorに限定した§6。詳細正本は[asset-management](../architecture/asset-management/README.md)

## 1. 背景と課題（Context）

既存正規化は型式と個体、N:M互換を分けている。一方、現物を使った検討では、セット別BAT表示を固定所有と誤読する危険と、中古機の不明な過去を管理開始00:00と混同する問題が具体化した。取得確認の記録と点検整備の実施者／転記者も、Entity属性の列挙だけでは判断理由を残せない。

## 2. 検討した選択肢（Options Considered）

- 旧スロット・機体セット表示を固定所有や最終タブ構造として採用する。
- 中古機を常にゼロから扱う、またはBATサイクル数から正確な過去時間を推定して埋める。
- 正規化を維持し、観測・未知・管理開始後の実績を分けて現在の個別判断を保持する。
- 点検整備の実施者本人だけにアプリ／Drive入力を要求する、または根拠資料に基づく転記者を分ける。

## 3. 決定内容（Decision）

99.2の現在ベースラインとして、型式／独立個体／互換、取得時状態／取得後履歴、取得前の不明／管理開始後累計、整備実施者／記録作成・転記者を区別する。個別の取得時短時間確認の扱いは条件を保ち、一般的な時間除外規則へ広げない。意味・因果の詳細正本は32a〜32c、属性は12b／12e／12fに定め、物理schemaは先取りしない。

## 4. 採用理由と他案の却下理由（Rationale）

固定所有は共用実態と矛盾するため採らない（[32b §1・§2](../architecture/asset-management/32b_battery-sharing-and-acquisition-history.md)）。一律ゼロ・過去時間の推定は、既知／不明と今回固有の根拠を失わせる（[32a §2・§3](../architecture/asset-management/32a_aircraft-acquisition-and-cumulative-time.md)）。実施者本人の入力だけに限ると外部業者資料に基づく記録が扱えない（[32c §3](../architecture/asset-management/32c_acquisition-check-and-maintenance-actors.md#3-実施者と作成転記者を分ける理由)）。各案の詳細因果はリンク先に一本化する。

## 5. メリット（Pros）

N機・M本や複数人の運用に拡張しても個体履歴と担当の事実が失われず、後から証拠が得られた場合も過去の判断を監査できる。表示・属性・運用意味を独立して変更できる。

## 6. デメリット・トレードオフ（Cons / Trade-offs）

単一の累計値や作成者列だけでは済まない。意味の分離を保存・表示へ落とす設計と実物確認が残り、その負担を本ADRで確定schemaへ置き換えない。基準Docsと未移植の§6保存構造等との比較も後続へ残る。

## 7. 将来この決定を見直す条件（Re-evaluation Triggers）

信頼できる前所有者記録、取得時証拠の訂正、共用関係や業務の変化、適用すべき公式根拠の具体化で前提が変わった場合に、各詳細正本の因果を保って見直す。ADR-0015の開始ゲート、0016の人物・権限の境界を維持し、§6全体・保存構造・通常整備運用の採用をこの記録から推論しない。
