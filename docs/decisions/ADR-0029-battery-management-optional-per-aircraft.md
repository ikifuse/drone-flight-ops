# ADR-0029: BAT管理を機体単位の任意とし、BAT管理と飛行記録の区切りを分離する

- **作成日**: 2026-09-20
- **ステータス**: Proposed（未承認）。現在の設計ベースラインの判断記録であり、ADR自体は未承認
- **関係性**: [ADR-0020](ADR-0020-flexible-flight-and-finalization.md)の柔軟な1飛行（BAT交換を含めて集約できる）と、[ADR-0007](ADR-0007-normalized-masters-and-business-reporting.md)の「飛行由来の使用履歴を別表へ二重保存しない」、[ADR-0017](ADR-0017-asset-acquisition-history-and-cumulative-scope.md)の「不明な過去を推定しない」をClarifiesし、BAT管理の適用範囲と現場入力を加える。Accepted本文は変更しない
- **決定者**: オーナーの2026-09-20の指示を、Claudeが記録
- **詳細正本**: [32e](../architecture/asset-management/32e_battery-management-scope-and-flight-separation.md)・[32g](../architecture/asset-management/32g_battery-field-input.md)。保存はADR-0028

## 1. 背景と課題（Context）

BAT個体管理は基準アプリのコアの強みだが、全利用者・全機体に必要とは限らない。中古機・中古BATで過去の履歴が既に不明な場合、これまでBAT管理をしておらず今後も望まない場合、100g未満の機体などでBAT個体管理を必要としない場合がある。また、BAT管理と飛行記録の区切りを同じにすると、BAT交換のたびにA4の飛行記録が分かれたり、BAT管理をしない機体の飛行記録が成り立たなくなったりする。

## 2. 検討した選択肢（Options Considered）

- A. 全機体でBAT管理を必須にする（旧の前提）。
- B. BAT管理を機体単位の任意とし、OFFの機体でも基本運用を完結させる。
- C. BAT交換を、A4の飛行記録の行の区切りとして使う。
- D. BAT管理のON／OFFを、飛行の区切りとは別の責任にする。

## 3. 決定内容（Decision）

BとDを現在の設計ベースライン（CURRENT-ACCEPTED）として32eに記録する。

- BAT管理を利用するかどうかは、機体単位で選べる。全利用者へ強制しない。OFFの機体でも、飛行記録・点検記録等の基本運用は完結できなければならない。
- BAT管理のON／OFFは、飛行の区切りとは別の責任である。同じ1飛行の途中でBATを何回交換しても、BAT交換だけを理由にA4の飛行記録を複数行へ分けない。BAT管理がONの場合だけ、その飛行の裏側にBAT使用履歴を関連付ける。
- ONの機体でBATの使用開始・交換時に人が扱う項目は、管理ラベル（必須）・サイクル数（任意）・状態確認（必須）・備考（任意）の4項目に絞る（32g）。サイクル数は、使用回数から推定して自動加算しない。使用日時・機体・飛行時間等、アプリが知る値は自動で記録する。
- BAT管理は新品に限らない。中古は、管理開始時点以降を管理し、不明な過去を推定して埋めない。
- 物理BATが機体の付属物でなく独立した個体であること（ADR-0007 §2.2）は、既存のAccepted決定として維持し、本ADRでは重ねて決めない。

状態確認の選択肢、ON／OFFの設定場所、A4のBAT欄の表記等は決めていない（`PENDING`）。

## 4. 採用理由と他案の却下理由（Rationale）

Aは、中古・履歴不明・BAT管理を望まない利用者や、BAT個体管理を必要としない機体の導入を妨げ、記入支援の目的にも合わないため採らない。Cは、1飛行に複数のBAT交換を含められる既存の柔軟な運用（ADR-0020）と食い違い、BAT管理の有無で飛行記録の構造が変わるため採らない。BとDにより、BAT管理を使う機体と使わない機体で、飛行記録・点検記録の基本運用を同じにできる。

## 5. メリット（Pros）

- 利用者と機体ごとにBAT管理の負担を選べ、導入の障壁が下がる。
- BAT管理の有無が、飛行記録の構造に影響しない。
- 現場入力が4項目に絞られ、確認忘れと操作負担を抑えられる。

## 6. デメリット・トレードオフ（Cons / Trade-offs）

- OFFの期間のBAT履歴は遡って作れない。ONに切り替えた時点以降を管理する（PENDING-D-BAT-SWITCH）。
- A4のBAT欄に、OFFの機体や、複数のBATを使った場合をどう表記するかは未確定（PENDING-D-BAT-A4-COLUMN）。
- 統合要件の飛行前後の残量や交換時の最小確認が、4項目に含まれない（PENDING-D-BAT-LEGACY-CHECKS）。
- 機体ごとのBAT管理の有無を保持する場所は、schemaとして未確定（PENDING-C1-SCHEMA）。

## 7. 将来この決定を見直す条件（Re-evaluation Triggers）

- OFFの機体で基本運用が成り立たないと分かった場合。
- 4項目では安全・保全に足りない、または現場の負担が大きいと実運用で分かった場合。
- オーナーがON／OFFの単位を変える場合。
