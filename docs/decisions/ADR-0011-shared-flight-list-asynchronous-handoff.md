# ADR-0011: 共有飛行リストを用いた非同期運航引継ぎ方式の採用

- **作成日**: 2026-09-18
- **ステータス**: **提案中（Proposed）**
- **決定者**: 検討中（99.2設計検討正本反映 / オーナー最終監査待ち）
- **関連設計**: [13b DIPS通報FSM](../architecture/state-machines/13b_dips-submission.md)、[新設予定: presentation](../architecture/presentation/README.md)、[24a DIPS通報台帳](../architecture/dips-submission/24a_submission-and-sheets-ledger.md)
- **関連ADR**: [ADR-0004](ADR-0004-dips-adapter-architecture.md)

## 1. 背景と課題（Context）

従来の計画作成・運航フローでは、「計画作成者がその場で通報し、直ちに同一人物が飛行前点検・離陸を行う」という単一セッションの同期的フローが暗黙の前提となっていました。
しかし、実際の業務運用や小規模チームでの運航では、
1. 事務担当者が前日や当日の朝に飛行計画を作成・DIPS通報し、現場の操縦者が後から計画を引き継いで飛行前点検を開始する。
2. 同一人物であっても、通信環境の良い場所で通報を済ませておき、現場へ移動した後に運航を開始する（時間差運用）。
という非同期な運用形態が存在します。通報と点検・離陸が密結合していると、通報完了画面を閉じた後に現場操縦者が計画を引き継ぐことが困難になります。

## 2. 検討した選択肢（Options Considered）

- **選択肢A: 同期的な単一セッションフローの強制**
  計画作成から通報、点検、離陸までを単一画面遷移として維持する案。通報者と現場操縦者が異なる分業運用や、時間差を伴う現場運用に対応できない。
- **選択肢B: 共有作業キュー（共有飛行リスト）を介した非同期引継ぎ（推奨案）**
  DIPS通報受領が確認された飛行計画を、環境共有の「飛行リスト（Working Queue）」へ反映し、現場操縦者がリストから対象計画を選択して飛行前点検を開始する方式。

## 3. 決定内容（Decision）

選択肢Bを Proposed として起票します。

1. **通報者と操縦者の分離**:
   - 飛行計画のデータ構造において、通報操作を行った人物と、現場で操縦する人物を独立して扱えるようにする。
2. **共有作業キュー（共有飛行リスト）への掲載**:
   - DIPS正常受付が確認された飛行計画は、共有台帳（06_DIPS関連／共有飛行リスト）へ掲載され、運航待機状態となる。
3. **現場での非同期引継ぎ**:
   - 現場操縦者はアプリの［飛行リスト］から自身が担当する計画を選択し、通報内容・空域の目視確認を経て、飛行前点検画面へ遷移する。
   - ※飛行の識別子体系、重複着手の制御方針（競合防止等）の具体的設計は、後続のデータモデル設計（Step 2, Step 5）において整合性を検証して確定する（PENDING）。

## 4. メリット（Pros）

- 事務担当者による事前通報と現場操縦者による実飛行の分業が可能になる。
- 通信環境の良い場所で事前通報を完了させ、必要な計画情報が現場端末へ事前に同期・キャッシュされていれば、現場が携帯電波微弱なエリアであっても運航を開始できる。
- 画面の中断や再起動に対する耐障害性が向上する。

## 5. デメリット・トレードオフ（Cons / Trade-offs）

- 通報済み計画の共有ストレージへの反映と、現場端末側でのキャッシュ同期が必要となる。
- 同一計画に対する複数操縦者による重複着手への注意喚起・制御設計が必要となる（未確定・PENDING）。

## 6. 今後の検証・昇格条件（Validation Criteria）
