# ADR-0010: 三層権限レイヤーの分離と運用環境所属境界の採用

- **作成日**: 2026-09-18
- **ステータス**: **提案中（Proposed）**
- **決定者**: 検討中（99.2設計検討正本反映 / オーナー最終監査待ち）
- **関連設計**: [16 セキュリティ・秘密情報](../architecture/16_security.md)、[12a 人員・組織](../architecture/domain-model/12a_organization-and-personnel.md)、[新設予定: identity-and-access](../architecture/identity-and-access/README.md)
- **関連ADR**: [ADR-0007](ADR-0007-normalized-masters-and-business-reporting.md)

## 1. 背景と課題（Context）

ドローン運航管理においては、現場の操縦者や記録者、事務担当の通報者、アプリの管理者、そして台帳が保管されるGoogle Driveのファイル共有設定など、多面的な役割と権限が交錯します。
検討段階では、人物の役割（操縦者等）とアプリの設定変更権限、Google Driveの共有権限（Viewer/Editor）が混同され、操縦者だからといって自動的にDrive Editorやアプリ管理者に昇格させるような権限設計に陥るリスクがありました。
また、将来の組織利用や複数パイロットへの展開を見据えた際、個人私用Googleアカウントへの依存を排除しつつ、現段階で過剰なマルチテナント基盤を構築せずに将来拡張を阻害しない境界を維持する必要があります。

## 2. 検討した選択肢（Options Considered）

- **選択肢A: Google Drive共有権限にアプリ権限を従属させる案**
  検討途中で候補となった案（Drive側の共有設定やwritersCanShare等をアプリ管理者保護に使う等）。しかし、アプリ管理者とGoogle Drive共有権限はレイヤーが異なるため不採用と判断した。また、アプリ内でEditorの承認・申請を行う案もGoogle標準共有との二重管理になるため不採用とした。
- **選択肢B: 三層権限レイヤーの分離と論理所属境界の定義（推奨案）**
  業務役割・機能権限・Drive実アクセス権を3つの独立したレイヤーとして分離し、個人利用を最小構成としつつ将来拡張のための所属境界（環境と人物の関係）を論理モデルとして維持する案。

## 3. 決定内容（Decision）

選択肢Bを Proposed として起票します。

1. **三層権限レイヤーの厳格な分離**:
   - **第1層：業務上の役割（Operational Roles）**: 操縦者、通報者、記録者、補助者等。運航業務・法令上の分担。
   - **第2層：アプリ機能上の権限（App Functional Permissions）**: 画面表示、計画作成、通常運航入力、設定変更（機体・BAT・人員マスター管理）の操作制御。具体的な権限マトリクスはStep 2で確定（PENDING）。
   - **第3層：Google Drive上の実アクセス権（Physical Drive Permissions）**: Google標準共有（Viewer/Editor等）。Google側を正本とし、アプリからDrive共有権限の自動変更は行わない。
2. **人物ロールと権限レイヤーの非混同**:
   - 操縦者であることやDrive Editorであることのみを理由に、アプリ管理者権限を自動付与しない。
3. **将来拡張境界の保護（YAGNI配慮）**:
   - 複数組織・複数ユーザー対応を将来阻害しないための所属境界概念（運用環境と人物の所属ライフサイクル、離任・再所属履歴）をデータモデル上で保護する。
   - 現段階で具体的なDBカラム名を固定化したり、複雑なマルチテナント管理UI/APIを先行実装しない。

## 4. メリット（Pros）

- 業務役割、アプリ機能権限、Google Drive共有権限が分離され、権限昇格バグや意図しないセキュリティ侵害を防止できる。
- 個人利用の軽量性を維持しながら、将来の組織展開・複数人運用に耐える論理境界が確保される。

## 5. デメリット・トレードオフ（Cons / Trade-offs）

- 運用者はGoogle Drive側の共有設定とアプリ内の人員マスター設定の両方を把握する必要がある（自動同期を行わないため）。
- 離任時・退職時は、アプリ内の所属終了操作とGoogle側の共有解除操作を別個に実施する必要がある。
