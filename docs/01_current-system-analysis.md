# 現行自作システムの機能・強み・弱み分析

最終更新: 2026-09-14
対象リポジトリ: `ikifuse/autel-evo-lite-flight-log`
現行バージョン: v1.0.0 (内部実装版 2026.09.09.3)

---

## 1. 現在の自作アプリの機能一覧

現行アプリは、Google Apps Script (GAS) および Googleスプレッドシートを基盤とし、現場での実機運用（Autel EVO Lite / EVO Lite+）に特化して構築されたWebアプリケーションです。

### 1.1 運航開始・条件入力機能
- **機体選択**: EVO Lite または EVO Lite+ を選択。
- **基本条件入力**: 飛行経路・場所、飛行目的、天候・風速・風向の記録（任意）。
- **飛行カテゴリー・飛行方法の判定**:
  - 通常飛行・屋内練習と9種類の特定飛行（空港等周辺、150m以上、DID、夜間、目視外、30m未満、催し場所上空、危険物輸送、物件投下）を選択可能。
  - 特定飛行を選択すると、カテゴリーⅠからカテゴリーⅡへ自動切り替えし、注意喚起トーストを通知。
- **人員情報管理**:
  - 操縦者名の保持、技能証明番号の記録。
  - 補助者の管理（「なし」「過去の履歴から選択」「新規入力」）。誤記防止のため前回の自動選択は行わない。
- **前回条件の引用**: 前回の運航場所や目的をワンタップで引用可能。

### 1.2 飛行前点検機能
- **11項目の法定日常点検**:
  - 機体全般、プロペラ・フレーム、通信系統、推進系統、電源系統、自動制御系統、バッテリー、操縦装置、灯火、カメラ、リモートID。
- **装着バッテリーの指定**: 装着中のバッテリー番号（`BAT_1`〜`BAT_7`）を必須指定。
- **サイクル数記録**: アプリ上で確認できた場合のバッテリー充電サイクル数記録（任意）。
- **異常検知・中止フロー**: 異常がある場合は異常内容を入力して「運航中止（PRE_ABNORMAL）」へ移行。不用意な帳票破壊を防止。

### 1.3 離着陸および飛行中管理機能
- **離陸記録**: ワンタップで離陸時刻（`HH:mm`）を打刻。飛行中画面へ移行。
- **飛行中画面**: 操縦を妨げないミニマルUI。飛行経過時間のリアルタイム計測表示。
- **着陸記録**: ワンタップで着陸時刻を打刻。
- **着陸後実績入力**: 実飛行時間（分）、安全に影響した事項、バッテリー所感の入力。
- **日跨ぎ飛行対応**: ISO形式の実時刻比較により、日付を跨ぐフライト（例: 23:55離陸〜00:10着陸）も正常に処理。

### 1.4 バッテリー交換および機体交代機能
- **同一機体でのバッテリー交換（BATTERY_CHANGE）**:
  - 全11項目の点検を省略し、バッテリー番号の再選択、装着・ロック、残量・温度・警告の最小確認だけで次のフライトへ素早く移行。
- **同一運航内での機体交代**:
  - EVO Lite ↔ EVO Lite+ の交代を同一セッション内でサポート。
  - 交代先機体で初回の飛行前点検を自動要求。
  - 帳票側でも機体ごとに別ブロック（No.1 / No.2）へ自動振り分け。

### 1.5 飛行後点検および一括保存機能
- **使用全機体の飛行後点検**: 4項目（機体全般、プロペラ・フレーム、発熱、その他）、点検場所、異常有無、不具合詳細の記録。
- **コミットエンジン（保存制御）**:
  - 運航全体を一意のUUIDで識別。
  - 二重保存防止（Idempotency）、リトライ耐性、通信障害時の安全復旧。
  - 端末内（LocalStorage）への自動下書き退避・復元。

### 1.6 スプレッドシート帳票・台帳連携機能
- **日常点検シート（国交省様式1・2相当）**:
  - 日付テンプレート原本から自動複製（`YYYY.M.D`）。同一日複数現場は連番対応（`_2`）。
  - 左右2ブロック（No.1 / No.2）構造により、最大7飛行×2または機体交代を綺麗に配置。
- **バッテリー個別履歴シート（`BAT_1`〜`BAT_7`）**:
  - 飛行ごとに1行ずつ、日付、機体、目的、飛行時間、所感を自動追記。
- **機体別原本（累計管理台帳）**:
  - 正式な機体累計飛行時間を原本マスターから読み取り、実績を加算して更新。
- **手修正後の計算継続機能**:
  - スプレッドシート側で人間が手動修正した場合、過去の履歴を壊さず、修正値を新たな基準として次回の計算を継続。
- **アプリテスト（シミュレーション）モード**:
  - 実機を飛ばさずに画面遷移や保存テストを行えるモード。テスト記録は機体正式累計から安全に除外。

## 2. 現在の自作アプリの強み

### ① 徹底したバッテリー個体管理（最大の差別化ポイント）
- 一般的なドローンアプリは「機体」と「操縦者」の記録にとどまることが多い中、**7本のバッテリーを個体識別番号（BAT_1〜BAT_7）で厳格に追跡**している。
- どのバッテリーを、どの機体で、何分飛ばし、どのような所感（電圧低下、発熱、膨らみ等）があったかを生涯記録として蓄積可能。
- 事故防止に最も重要な電源系統の健康管理が完璧に行える。

### ② 現場のオペレーションに即した状態遷移
- 現場で1フライトごとに全点検をやり直す不合理を排除し、「バッテリー交換時の最小確認フロー」を備えている。
- 1つの運航の中で「予備機への交代」が発生しても、迷わず自然に画面を進められる。
- 現場でのワンオペ（一人作業）を前提とした、手数の少ないUI設計。

### ③ スプレッドシートを正本とする透明性と監査性
- データベースが専用クラウドにブラックボックス化されておらず、Googleスプレッドシートという汎用的かつ人間が直接触れる形式で保存されている。
- 国土交通省の検査官や取引先に見せる際も、そのまま共有・閲覧・PDF印刷が可能。
- 人間が数値を手修正してもシステムが壊れない「手修正追従（計算継続）」の思想が実装されている。

### ④ 堅牢な保存アーキテクチャ（ロストゼロ思想）
- 電波が不安定な屋外での利用を想定し、UUIDによる冪等性管理、端末内下書き退避、重複送信ガードが極めて綿密に設計されている。
- 通信エラーが発生してもデータが失われず、安全に再試行できる。

## 3. 現在の自作アプリの弱み・制約事項

### ① DIPS 2.0との連携が完全に欠如
- 国土交通省への「飛行計画の通報」や「許可承認番号の照会」「機体登録情報の照会」が一切行えない。
- 現場では別途ブラウザ等でDIPS 2.0にログインして手動で計画を通報・確認しなければならず、二度手間が発生している。

### ② 地図表示および飛行範囲（ポリゴン・円）の指定ができない
- 飛行場所や飛行経路がテキスト入力（手動入力）にとどまっており、地図UI上で視覚的にエリアを指定・確認する機能がない。
- 国交省の飛行禁止エリア（空港周辺、DID地区、米軍空域等）の確認もアプリ内では行えない。

### ③ 機体・バッテリーが固定（ハードコード）
- システムが「Autel EVO Lite / EVO Lite+」および「BAT_1〜BAT_7」の2機体・7バッテリーに強く依存して作られており、機体を増やしたり他メーカー（DJI等）の機体を導入する際の汎用性がない。

### ④ 完全オフライン環境での初期動作
- Google Apps Script (GAS) のWeb Appとして稼働しているため、初期読み込みや保存完了時にはオンライン通信が必要となる。山間部などの完全圏外では運用が制限される。

### ⑤ 外部標準帳票（国交省標準PDF等）の直接出力がない
- 出力先がGoogleスプレッドシートのみであり、ボタン1つで国交省様式1〜3のPDFや、地図付き飛行計画書、汎用CSV/Excelを直接ダウンロードする機能がない。

### ⑥ 有効期限の監視・事前警告がない
- 機体登録の有効期限（3年）、包括飛行許可承認の期限（1年）、操縦者の技能証明・身体適性期限などのカウントダウン警告がなく、期限切れに気づきにくい。
