# 参考アプリ（ワンエビneo）の機能分析と現行システムとの比較

最終更新: 2026-09-14
参考アプリ: DIPS Viewer ワンエビneo（ドローンフォーオール社）
調査元資料: 非公開調査メモ（`autel-evo-lite-flight-log-private-notes`）および公開機能一覧

## 1. ワンエビneoの参考機能一覧

「DIPS Viewer ワンエビneo」は、国土交通省のDIPS 2.0システムとの直接連携および飛行計画通報、国交省標準様式の日誌出力を中心とした民間運航管理・支援アプリです。

以下は、公開情報および調査メモから確認された主な機能群です。

### 1.1 DIPS 2.0 直接連携機能
- **DIPS登録機体の取得・表示**:
  - DIPS機体登録システム（DRS/UTM API: `GET /utm/v1/aircrafts`）から、ユーザーが保有・登録している機体一覧（登録記号、機体名、シリアル等）を取得して表示。
- **飛行許可・承認情報の取得・表示**:
  - DIPS飛行許可承認システム（FPA/REQ API: `GET /permissions`）から、現在有効な許可・承認書番号、適用期間、飛行区分（DID、夜間、目視外等）を取得して表示。
- **飛行計画の取得・検索・表示**:
  - DIPS飛行計画通報システム（FPR/FPL API）から、既存の飛行計画を検索・取得し、地図上および一覧に表示。
- **DIPSへの飛行計画通報（FPR）**:
  - アプリ上で作成した飛行計画データをJSON化し、DIPS 2.0へ直接通報（POST送信）。
- **DIPSエラー理由のユーザー向け表示**:
  - 通報失敗時、DIPS側から返されたバリデーションエラーや理由コードを解析し、修正箇所をわかりやすく提示。
- **通報後の再取得・ステータス更新**:
  - 通報完了後、最新の飛行計画一覧を再照会し、正式な通報IDを取得して反映。

### 1.2 地図・飛行範囲作成機能
- **円形範囲の作成**:
  - 地図上で中心点（緯度・経度）を指定し、半径（m）を入力して円形の飛行空域を定義。
- **ポリゴン（多角形）範囲の作成**:
  - 地図上をタップして複数の頂点を配置し、複雑な地形や施設境界に沿ったポリゴン飛行範囲を作成。
- **過去通報の複製・再利用**:
  - 過去に通報した飛行範囲や飛行計画の諸条件をワンタップで複製し、日時だけを変更して素早く再通報。
- **既定値の保持**:
  - 頻繁に利用する基本高度、連絡先、操縦者等のデフォルト値を端末内に保持。

### 1.3 機体管理および期限管理機能
- **複数機体の登録・管理**:
  - 複数のメーカー・機種の機体を柔軟に管理。
- **機体愛称（ニックネーム）設定**:
  - 複雑な登録記号やシリアル番号に対し、操縦者が識別しやすい任意の愛称を紐付け。
- **機体ごとの記憶**:
  - 機体ごとの前回設定値、利用実績を個別に記憶。
- **期限管理・警告**:
  - 機体登録の有効期限、許可承認の有効期限などを監視し、満了前に警告表示。

### 1.4 飛行計画と飛行日誌の連携
- **計画から日誌へのシームレス連携**:
  - DIPSへ通報した飛行計画情報（機体、場所、予定時間、目的、許可承認）を、実績入力用の飛行日誌へそのまま引き継ぎ。二重入力を排除。

### 1.5 帳票出力・データ入出力機能
- **多様な出力形式**:
  - PDF出力、CSV出力、Excel出力に対応。
- **国土交通省様式1〜3への準拠**:
  - 法定の「飛行記録（様式1）」「日常点検記録（様式2）」「点検整備記録（様式3）」のレイアウトで帳票化。
- **地図付き飛行計画PDF**:
  - 通報した飛行範囲（地図画像付き）を含む飛行計画書の印刷・出力。
- **CSV取込機能**:
  - 外部で作成した飛行データや過去記録をCSV形式で一括インポート。

### 1.6 端末ローカル保存・オフライン対応
- **端末内保存**:
  - アカウント情報、既定値、過去ログを端末内（LocalStorage / IndexedDB）に保持。
- **オフライン閲覧**:
  - 通信が不安定な現場でも、保存済みデータの確認やドラフト作成が可能。

## 2. 自作アプリとワンエビneoの重複機能

両者の機能構成を突き合わせると、以下の領域で目的と管理項目が重複しています。

| 管理領域 | 現行自作アプリの対応状況 | ワンエビneoの対応状況 |
|---|---|---|
| **機体基本情報の保持** | 保持（EVO Lite / Lite+ 固定） | 保持（DIPS取得＋任意機体） |
| **操縦者・補助者情報の管理** | 保持（履歴引用・誤記防止UI） | 保持（既定値保存） |
| **飛行目的・日時の記録** | 保持（開始条件で入力・打刻） | 保持（計画時および日誌時） |
| **飛行場所の指定** | テキスト入力 | 地図（円・ポリゴン・緯度経度） |
| **特定飛行区分の管理** | 9項目・カテゴリー自動判定 | 許可承認と連携した指定 |
| **飛行前後の点検** | 11項目（前点検）＋4項目（後点検） | 国交省様式2準拠の点検 |
| **離着陸時刻・実時間の記録** | ワンタップ打刻＋実時間入力 | 実績入力機能 |
| **飛行日誌（様式1相当）の作成** | スプレッドシートへ自動生成 | PDF/Excel/CSVへ自動生成 |
| **過去設定の再利用** | 前回運航条件の引用 | 過去通報・計画の複製 |

## 3. 両者のアプローチと運用思想の違い

### ① DIPS連携と外部システム接続
- **ワンエビneo**:
  - 「DIPS 2.0公式との接続」を中核価値とし、通報業務の効率化と法令上の通報義務の自動化に特化。
- **自作アプリ**:
  - 外部APIへの依存を排し、「現場での迷わない操作と堅牢なデータ蓄積」に特化。

### ② バッテリー管理の深度
- **ワンエビneo**:
  - 一般的な機体単位・飛行単位の記録にとどまり、バッテリー個体ごとの詳細な充放電・健康状態・交換サイクルの追跡は主機能ではない。
- **自作アプリ**:
  - 7本のバッテリーをシリアル単位で個体管理し、飛行時間・所感・機体との組み合わせを一生涯追跡する設計（強力な独自性）。

### ③ データの正本と透明性
- **ワンエビneo**:
  - アプリ内部または専用バックエンドにデータを保持し、最終成果物としてPDF/Excelを出力。
- **自作アプリ**:
  - Googleスプレッドシートそのものを正本（台帳）とし、人間が直接閲覧・手動加筆・修正でき、手修正後も数式や集計が追従するオープンなアーキテクチャ。
